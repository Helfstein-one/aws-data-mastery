Modern Data Integration

ELT, SaaS & AWS Zero-ETL

O paradigma mudou. Por que processar dados em voo com clusters pesados se você pode carregar dados brutos nativamente e processar via SQL ou até mesmo eliminar os pipelines com Zero-ETL?

01. O Paradigma

ETL Clássico vs ELT Moderno

Por muito tempo, o custo de armazenamento no banco analítico era caríssimo, então era obrigatório transformar os dados em voo (ETL) antes de persistir. Hoje, com S3 (Lakehouse) e Snowflake/Redshift, o storage é quase de graça e o compute escala ao infinito.

Característica ETL (Extract, Transform, Load) ELT (Extract, Load, Transform)
Local da Transformação Em memória/Cluster externo (ex: AWS Glue/Spark) Dentro do DW/Lakehouse usando SQL (ex: dbt)
Complexidade de Ingestão Alta. Se a regra de negócio muda, reprocessa tudo no Spark. Baixa. Copia raw 1:1, a transformação é flexível depois.
Ferramentas Chave Informatica, Talend, AWS Glue Airbyte, Fivetran, Stitch, dbt
02. System Design

Ingestão SaaS via Airbyte/Fivetran

Manter código customizado em Python para consumir APIs do Salesforce, Zendesk ou Stripe é um pesadelo de manutenção. A engenharia moderna terceirizou a ponta da Ingestão para conectores open-source (Airbyte) ou SaaS (Fivetran).

03. Inovação AWS

AWS Zero-ETL Integrations

O que é melhor do que um pipeline ELT fácil de gerenciar? Não ter pipeline. A AWS lançou as integrações Zero-ETL, onde as transações de um banco relacional ficam disponíveis quase em tempo real no Redshift sem usar Lambda, DMS ou Kinesis.

🚀 Aurora to Redshift Zero-ETL

O storage backend do Amazon Aurora replica de forma transparente as alterações físicas diretamente para o cluster do Redshift em poucos segundos. Você apenas executa queries analíticas nos dados vivos.

🔍 DynamoDB to OpenSearch

Em vez de configurar DynamoDB Streams + Lambda para manter índices de busca sincronizados, o Zero-ETL mapeia automaticamente os inserts do DynamoDB para o OpenSearch Serverless.

📉 Vantagens de Custo

Você não paga por clusters transitórios de ETL. Paga apenas pelo armazenamento e pelo tempo de processamento da query no destino.

04. O Motor por Trás

Change Data Capture (CDC)

Tanto as ferramentas modernas de ELT (Airbyte) quanto o AWS Zero-ETL não ficam rodando "SELECT * FROM tabela" de hora em hora. Isso mataria o banco de produção. Eles utilizam CDC (Change Data Capture), lendo diretamente os arquivos físicos de log do banco de dados (WAL no PostgreSQL, Binlog no MySQL).

05. Prática Analítica

Consumindo Zero-ETL no Amazon Redshift

Na AWS, quando você cria uma integração Zero-ETL entre um cluster Aurora MySQL e o Redshift, você não escreve um pipeline. Você apenas aceita a integração e cria um banco de dados federado no Redshift.

Redshift Query Editor SQL
-- 1. Cria o banco de dados no Redshift apontando para o identificador da integração Zero-ETL CREATE DATABASE my_aurora_integration FROM INTEGRATION 'arn:aws:rds:us-east-1:123456789012:integration:11111-2222-3333-4444'; -- 2. Imediatamente (com segundos de delay), você pode consultar os dados do Aurora VIVOS! SELECT u.country, COUNT(o.order_id) AS total_orders, SUM(o.amount) AS total_revenue FROM my_aurora_integration.sales_db.users u JOIN my_aurora_integration.sales_db.orders o ON u.id = o.user_id WHERE o.created_at > CURRENT_DATE - INTERVAL '7 days' GROUP BY 1;
06. Estudo de Caso

Migração de Pipelines API para Fivetran/Airbyte

O Problema: Uma startup de e-commerce mantinha 40 scripts em Lambda (Python) para baixar dados do Zendesk, Shopify, Facebook Ads e Google Analytics. Eles gastavam 60% do tempo dos engenheiros consertando os scripts porque as APIs de origem mudavam constantemente ou quebravam por Rate Limiting.

A Solução ELT:

🗑️ Fim do Código Customizado

Todos os 40 scripts foram deletados. Eles configuraram conectores do Fivetran/Airbyte que nativamente lidam com paginação, backoff e rate limits das APIs. Os dados crus foram jogados diretamente no Snowflake/Redshift.

🔧 Transformação no DW

Os Engenheiros de Dados passaram a atuar como Analytics Engineers, usando o dbt (SQL) dentro do Redshift para tratar os JSONs sujos do Zendesk e juntar com os dados do Shopify, agregando valor imediato ao negócio.
