Analytics Engineering

dbt (Data Build Tool) no Lakehouse

Do caos das dezenas de scripts soltos para a verdadeira Engenharia de Software focada em Dados. Descubra como o dbt orquestra SQL escalável, transformando o Modern Data Stack no AWS Athena + Iceberg.

01. O Paradigma Moderno

A Ascensão do Analytics Engineer

Antigamente, as regras de negócios ficavam espalhadas em Views no banco, procedures pesadas ou em infinitos jobs do Spark (Python/Scala). Com a escalabilidade da nuvem (Data Warehouses e Lakehouses), processar SQL pesado deixou de ser o problema. O problema passou a ser: Como versionar, testar e orquestrar centenas de queries SQL com dependências complexas? O dbt preencheu essa lacuna.

🛠️ Tudo é SQL (com superpoderes)

O dbt utiliza Jinja para injetar lógica (if, loops, macros) dentro do SQL padrão. Se você sabe SQL e Jinja, você pode construir pipelines inteiros sem tocar em Python.

🔗 Linhagem Dinâmica (DAG)

Ao usar a função {{ ref('modelo_base') }}, o dbt entende exatamente quem depende de quem. Ele compila um DAG (Directed Acyclic Graph) automaticamente e roda as queries na ordem correta.

🧪 Testes e Documentação

Defina via YML testes como unique ou not_null e documente cada coluna. O dbt gera um site estático e roda querys para validar seus dados a cada execução.

02. System Design

Orquestrando dbt com Amazon Athena + Iceberg

O dbt não processa dados. Ele apenas compila o SQL e submete para um Compute Engine. Na AWS, o parceiro ideal para processamento serverless no S3 é o Amazon Athena integrado ao Apache Iceberg.

Fluxo de orquestração: Airflow dispara uma task dbt run num container (ECS), que envia a query compilada pro Athena processar os dados Iceberg no S3.

03. Engrenagens

Modelagem e Materializações

Uma materialização define como a sua query será compilada e executada no banco alvo. No universo Iceberg + Athena, o dbt-athena (adaptador) traduz essas instruções.

View (Camada Bronze/Staging)

Cria apenas uma "lente" em cima dos dados crus. Rápido, não consome storage, mas repete o processamento na leitura.

{{ config(materialized='view') }}

Table (Camada Silver/Gold)

Processa o select e salva o resultado fisicamente (ex: Iceberg V2). Rápido para ler, mas Drop/Create em todo refresh.

{{ config(materialized='table') }}

🔥 A Joia da Coroa: incremental

O grande desafio da Engenharia de Dados é o processamento incremental. O dbt facilita isso usando merge do Apache Iceberg nativamente.

models/silver/stg_transacoes_iceberg.sql Jinja + SQL
{{ config( materialized='incremental', incremental_strategy='merge', unique_key='transacao_id', table_type='iceberg' ) }} WITH raw_data AS ( SELECT id AS transacao_id, user_id, amount, created_at FROM {{ ref('raw_pagamentos') }} ) SELECT * FROM raw_data {% if is_incremental() %} -- Só processa dados novos em execuções após o primeiro run (full-refresh) WHERE created_at >= (SELECT MAX(created_at) FROM {{ this }}) {% endif %}
04. Qualidade de Dados

Testes Integrados ao Pipeline (YAML)

Antes do dbt, rodar testes (como asserts no Airflow ou Great Expectations) era um passo à parte, e costumava quebrar tarde. Com o dbt, o teste é vizinho do modelo.

models/schema.yml YAML
version: 2 models: - name: stg_transacoes_iceberg description: "Camada silver de transações tratadas com MERGE no Iceberg" columns: - name: transacao_id tests: - unique - not_null - name: amount tests: - accepted_values: values: ['> 0']
