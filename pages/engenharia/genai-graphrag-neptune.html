GraphRAG & Grafos de Conhecimento

Rompendo o limite do VectorDB com raciocínio multi-salto através do Amazon Neptune.

01

O Limite do VectorDB Clássico

Porque vetores falham na conexão de pontos distantes.

Bancos de dados vetoriais (OpenSearch, Pinecone, pgvector) são incríveis para buscar similaridade semântica. No entanto, eles falham miseravelmente quando a pergunta do usuário exige navegação complexa por relacionamentos (Multi-hop reasoning).

O Problema: Se você perguntar: "Quais diretores que trabalharam na Empresa A também investiram na Startup B?", o RAG tradicional tentará recuperar textos isolados. Ele provavelmente recuperará pedaços irrelevantes e falhará em conectar os pontos se eles estiverem em documentos diferentes.
02

A Solução: GraphRAG

Unindo a abstração do LLM com a precisão dos Grafos.

GraphRAG une a abstração semântica dos LLMs com a precisão relacional estruturada dos Grafos de Conhecimento (Knowledge Graphs). Em vez de extrair pedaços de texto brutos, extraímos Entidades e Relacionamentos.

📌 Legenda & Arquitetura — Knowledge Graph Ingestion (GraphRAG):
  • Componentes AWS / Módulos: Amazon Neptune (Graph Database), Amazon Bedrock (LLM - Extração de Triplas), Amazon S3 (Raw Text Storage), AWS Lambda / S3 Event Trigger.
  • Integração: Ingestão de texto bruto no S3, extração de entidades/relacionamentos (nós e arestas) via Bedrock LLM e escrita estruturada no banco orientado a grafos Amazon Neptune.
  • Contexto: Construção automatizada de Grafos de Conhecimento para suporte a consultas GraphRAG complexas.
1. Extração

Bedrock

Você passa documentos para um LLM extrair Triplas: (Sujeito) -> [Predicado] -> (Objeto).

2. Armazenamento

Amazon Neptune

As conexões são salvas em um banco especializado (suporta Gremlin ou openCypher).

3. Execução

Query

Na hora da pergunta, geramos uma query (Text-to-Cypher) e devolvemos o sub-grafo exato como contexto!

03

Arquitetura Híbrida: Vetor vs Grafo

A arquitetura ideal Enterprise usa os dois em conjunto.

Trade-off Table: Modelos de Busca RAG

Cenário de Busca Tecnologia Vencedora Por quê?
"Quais os riscos descritos no PDF de compliance do ano passado?" VectorDB (OpenSearch) Busca conceitual e texto puro. Não tem um caminho relacional forte, é pura semântica.
"Quais filiais compartilham fornecedores atrasados?" Knowledge Graph (Neptune) Mapeia relações exatas: (Filial) -> [COMPRA_DE] -> (Fornecedor) -> [TEVE] -> (Atraso).
"Ache processos criminais sobre fraude ligados à rede do executivo Y." Híbrido (Vetor + Grafo) Vetor acha o "padrão de fraude" (abstrato). Grafo acha a "rede de contatos". RAG junta os dois!
Exemplo: Extraindo Conhecimento com Cypher (Neptune) 
MATCH (d:Diretor)-[:TRABALHOU_EM]->(e:Empresa {nome: "Empresa A"})
MATCH (d)-[:INVESTIU_EM]->(s:Startup {nome: "Startup B"})
RETURN d.nome, d.cargo

O LLM recebe esses resultados diretos, garantindo **0% de alucinação** em interligações lógicas complexas!

04

GraphRAG na Prática — Neptune + Bedrock

Pipeline Text-to-Cypher: o LLM gera a query, o Neptune executa, o Bedrock sintetiza a resposta.

O pipeline GraphRAG completo usa o Amazon Neptune Analytics como grafo de conhecimento e a Bedrock Converse API para duas tarefas: gerar a query Cypher a partir de linguagem natural, e sintetizar a resposta final com o contexto do grafo. Zero alucinação em relacionamentos — o LLM nunca "inventa" conexões porque o grafo é a fonte da verdade.

Pipeline GraphRAG — Text-to-Cypher com Neptune e Bedrock
import boto3, json

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")
neptune = boto3.client("neptunedata", region_name="us-east-1",
                       endpoint_url="https://<cluster>.cluster.neptune.amazonaws.com:8182")

SCHEMA = """
Nós: Empresa(nome, setor), Diretor(nome, cargo), Startup(nome, valuation)
Arestas: (Diretor)-[TRABALHOU_EM]->(Empresa), (Diretor)-[INVESTIU_EM]->(Startup)
"""

def text_to_cypher(pergunta: str) -> str:
    resp = bedrock.converse(
        modelId="anthropic.claude-3-5-haiku-20241022-v1:0",
        messages=[{"role": "user", "content": [{"text": (
            f"Schema do grafo:\n{SCHEMA}\n\n"
            f"Gere APENAS uma query Cypher válida para responder: {pergunta}\n"
            "Retorne só a query, sem explicação."
        )}]}]
    )
    return resp["output"]["message"]["content"][0]["text"].strip()

def executar_cypher(query: str) -> list:
    result = neptune.execute_open_cypher_query(openCypherQuery=query)
    return result.get("results", [])

def graphrag_answer(pergunta: str) -> str:
    cypher = text_to_cypher(pergunta)
    dados  = executar_cypher(cypher)

    resp = bedrock.converse(
        modelId="anthropic.claude-3-5-sonnet-20240620-v1:0",
        messages=[{"role": "user", "content": [{"text": (
            f"Dados extraídos do grafo:\n{json.dumps(dados, ensure_ascii=False)}\n\n"
            f"Pergunta: {pergunta}\n"
            "Responda de forma concisa e direta, baseado exclusivamente nos dados acima."
        )}]}]
    )
    return resp["output"]["message"]["content"][0]["text"]

# Exemplo de uso
resposta = graphrag_answer(
    "Quais diretores que trabalharam na Empresa A também investiram em startups de IA?"
)
print(resposta)
