Módulo: IA & GenAI

Model Context Protocol na AWS

O MCP é um padrão de código aberto para conectar modelos de inteligência artificial (LLMs) a fontes de dados corporativas de forma segura, bidirecional e universal usando a nuvem AWS.

01

O que é o MCP?

Protocolo universal e aberto para conectar LLMs a dados e ferramentas externas de forma padronizada.

O Model Context Protocol (MCP) é um padrão universal e aberto, criado pela Anthropic, projetado para padronizar como os Large Language Models (LLMs) acessam dados e ferramentas externas. Antes do MCP, desenvolvedores precisavam criar integrações customizadas e específicas para cada modelo (ex: plugins do OpenAI vs ferramentas do Claude). Com o MCP, você escreve um servidor de dados ou ferramentas uma única vez e qualquer cliente compatível com MCP pode acessá-lo imediatamente.

Orquestrador
MCP Host
A aplicação que o usuário final interage e que gerencia o LLM. O Host (como Claude Desktop, AWS Bedrock Agents, ou Cursor IDE) é responsável por receber o prompt do usuário, decidir se deve invocar as ferramentas via MCP, e renderizar a resposta final.
Servidor de Dados
MCP Server
Um serviço leve e focado que obedece ao protocolo e se conecta às fontes de dados. Na Engenharia de Dados AWS, isso pode ser um container ECS ou uma função Lambda que sabe consultar o Amazon Athena, ler arquivos do S3, ou acessar um RDS PostgreSQL.
Conector de Protocolo
MCP Client
Um componente que vive dentro do Host e que mantém a conexão de protocolo (geralmente sobre stdio para processos locais ou SSE - Server-Sent Events para conexões remotas via HTTP) com o(s) Servidor(es) MCP, enviando requisições JSON-RPC.
ARCHITECTURE DIAGRAM — MCP CORE PROTOCOL
📌 Legenda & Arquitetura — Protocolo MCP (Host & Server Core):
  • Componentes AWS / Módulos: Amazon Bedrock (MCP Host), AWS Lambda / ECS Fargate (MCP Server), Python MCP SDK, Amazon Athena, Amazon S3.
  • Integração: Protocolo bidirecional JSON-RPC 2.0 (stdio/SSE) conectando o MCP Host no Bedrock ao MCP Server para exposição de ferramentas (Tools), recursos (Resources) e templates de prompt (Prompts).
  • Contexto: Padronização de contexto dinâmico e execução segura de ações em arquiteturas baseadas em Model Context Protocol.

Primitivas do Protocolo

O MCP define três primitivas fundamentais que os servidores podem expor para os clientes:

  • Resources (Recursos): Dados estruturados ou não estruturados estáticos que provêm contexto, como ler o schema de uma tabela do Glue ou baixar um arquivo Parquet de metadados.
  • Prompts (Templates): Templates de mensagens pré-definidos que os usuários ou aplicações podem invocar e que o servidor pode preencher dinamicamente com informações contextuais antes de enviar ao LLM.
  • Tools (Ferramentas): Funções executáveis. O LLM propõe chamar uma Tool (como executar uma query SQL) e o Cliente executa essa chamada no Servidor, retornando o resultado (ex: dados da query) para o LLM.
02

Construindo um Servidor MCP (Python SDK)

Implementação prática com FastMCP, decoradores e transporte stdio para projetos AWS.

A Anthropic disponibiliza SDKs oficiais para TypeScript e Python. Construir um servidor envolve inicializar o framework mcp.server.fastmcp, registrar ferramentas com decoradores e iniciar o transporte (stdio é o mais simples e ideal para ser rodado como um processo filho pelo Host).

python mcp_athena_server.py 
from mcp.server.fastmcp import FastMCP
import boto3
import time
import pandas as pd
from typing import Any

# 1. Inicializamos o servidor
mcp = FastMCP("AWS Data Engineering MCP Server")
athena_client = boto3.client('athena')

# 2. Registramos uma ferramenta usando o decorador @mcp.tool()
@mcp.tool()
def query_athena(database: str, query: str) -> str:
    """
    Executa uma query SQL no Amazon Athena e retorna os primeiros 100 resultados
    formatados como Markdown. Útil para extrair insights da camada Lakehouse.
    """
    
    # Executa a query
    response = athena_client.start_query_execution(
        QueryString=query,
        QueryExecutionContext={'Database': database},
        ResultConfiguration={'OutputLocation': 's3://meu-bucket-athena-results/'}
    )
    
    query_id = response['QueryExecutionId']
    
    # Aguarda a conclusão (Simplificado)
    while True:
        status = athena_client.get_query_execution(QueryExecutionId=query_id)
        state = status['QueryExecution']['Status']['State']
        if state in ['SUCCEEDED', 'FAILED', 'CANCELLED']:
            break
        time.sleep(2)
        
    if state != 'SUCCEEDED':
        return f"Erro na execução da query: {state}"
        
    # Lê os resultados
    results = athena_client.get_query_results(QueryExecutionId=query_id)
    
    # Extrai colunas e linhas
    columns = [col['Label'] for col in results['ResultSet']['ResultSetMetadata']['ColumnInfo']]
    rows = []
    
    for row in results['ResultSet']['Rows'][1:101]: # Pula header, pega top 100
        row_data = [item.get('VarCharValue', '') for item in row['Data']]
        rows.append(row_data)
        
    # Converte para DataFrame e depois Markdown
    df = pd.DataFrame(rows, columns=columns)
    return df.to_markdown(index=False)

# 3. Rodamos o servidor
if __name__ == "__main__":
    # Inicia escutando no stdin/stdout para o protocolo JSON-RPC
    mcp.run(transport='stdio')
💡
Por que o Docstring é vital? O texto no Docstring da função Python não é apenas documentação para o desenvolvedor. Ele é transmitido diretamente para o LLM. O Claude/Titan lerá esse docstring para entender quando e por que ele deve usar a ferramenta query_athena, bem como o formato dos parâmetros esperados. A tipagem (type hints) também é automaticamente convertida em JSON Schema.

Recursos e Server-Sent Events (SSE)

Resources, templates de prompt e comunicação remota com HTTPS/SSE em servidores MCP.

Além das ferramentas, um caso de uso comum na Engenharia de Dados é fornecer contexto estático, os chamados Resources. Resources seguem um formato de URI (ex: s3://meu-bucket/schema.json). Diferente das Tools, os resources podem ser injetados diretamente no prompt do usuário pelo Host, economizando tokens e melhorando a precisão.

python mcp_s3_resources.py 
from mcp.server.fastmcp import FastMCP
import boto3

mcp = FastMCP("Data Dictionary Server")
s3 = boto3.client('s3')

# Registra um recurso utilizando template URI
@mcp.resource("s3://data-dictionary/{database}/{table}.md")
def get_table_schema(database: str, table: str) -> str:
    """
    Recupera a documentação técnica (Dicionário de Dados) 
    de uma tabela específica do Lakehouse.
    """
    try:
        response = s3.get_object(
            Bucket='data-dictionary-corp', 
            Key=f'{database}/{table}.md'
        )
        return response['Body'].read().decode('utf-8')
    except Exception as e:
        return f"Dicionário de dados não encontrado para {database}.{table}"
        
if __name__ == "__main__":
    # Em um ambiente Serverless ou containerizado (ECS Fargate/AppRunner),
    # o stdio não é viável. Utilizamos SSE para expor um endpoint HTTP REST/EventStream.
    mcp.run(transport='sse', port=8080)

Ao usar o transport='sse', o FastMCP inicia um servidor web FastAPI/Starlette que pode ser acessado remotamente pelo seu MCP Host (como o Bedrock Agent), permitindo centralizar um servidor de contexto corporativo seguro em um VPC AWS fechado.

Arquitetura Corporativa: API Gateway, ALB e ECS

Deploy escalável e seguro do MCP Server via API Gateway, ALB e ECS Fargate na AWS.

Em cenários corporativos, você raramente executará um servidor MCP via linha de comando (stdio) localmente na mesma máquina do usuário. O modelo de maturidade ideal envolve hospedar o MCP Server em um cluster elástico na nuvem AWS, expondo os Tools e Resources de forma segura para diversos LLMs e aplicações clientes externas.

ARCHITECTURE DIAGRAM — ENTERPRISE MCP DEPLOYMENT
📌 Legenda & Arquitetura — Implantação Corporativa MCP Server via SSE:
  • Componentes AWS / Módulos: Amazon API Gateway (WAF/Auth/Rate Limiting), Application Load Balancer (ALB, persistent SSE), AWS ECS Fargate (FastMCP cluster, VPC privado), Amazon Athena (Tool: SQL), Amazon S3 (Resource: arquivos).
  • Integração: Comunicação HTTPS/SSE do MCP Host externo roteada pelo API Gateway (autenticação Cognito/IAM) → ALB (Target Groups) → Fargate containers com FastMCP Server, que acessa Athena e S3 via IAM Task Role + VPC Endpoints.
  • Contexto: Arquitetura corporativa de alta disponibilidade, escalabilidade automática e isolamento de rede para servidores MCP na AWS com conexões SSE persistentes.

Componentes da Topologia

  • 1. API Gateway (REST API / HTTP API): Atua como o ponto de entrada único (Single Point of Entry). É responsável por interceptar a chamada do cliente MCP (ex: Claude Desktop), validar a autenticação (via Cognito, IAM ou API Keys), e aplicar proteções como Rate Limiting e integração com AWS WAF contra ataques de negação de serviço.
  • 2. Application Load Balancer (ALB): O API Gateway faz o proxy reverso para um ALB interno. O ALB distribui o tráfego de maneira inteligente entre os múltiplos containers disponíveis. Para conexões via Server-Sent Events (SSE), o ALB é capaz de manter a conexão persistente e transmitir os pacotes contínuos.
  • 3. Amazon ECS (Fargate): Onde o servidor FastMCP efetivamente reside em containers Serverless. O serviço roda de forma elástica, inicializando via mcp.run(transport='sse', host='0.0.0.0'). Os containers não precisam possuir IP público, residindo em sub-redes privadas e acessando os dados (S3, Athena, RDS) através de VPC Endpoints ou rotas internas, garantindo conformidade com a segurança da organização.
⚠️
SSE Timeout e Persistência Diferente de chamadas REST comuns de curta duração, o transporte SSE no MCP exige que as conexões fiquem abertas enquanto a sessão de contexto durar. Ao projetar essa arquitetura, preste muita atenção aos Idle Timeouts do API Gateway (máximo de 29 segundos para HTTP APIs) e do ALB. Para sessões longas de MCP contínuo em produção, frequentemente substitui-se o API Gateway diretamente por um ALB público com TLS (WAF atrelado ao ALB) ou adota-se WebSocket API no API Gateway.
05

Integrações Nativas com Serviços AWS

Como expor Athena, Glue, DynamoDB, S3 e RDS como Tools e Resources do seu MCP Server.

Qualquer serviço AWS acessível via SDK Boto3 pode ser transformado em uma Tool (ação executável) ou Resource (dado de contexto) de um MCP Server. A tabela abaixo mapeia as primitivas MCP aos serviços mais relevantes para Engenharia de Dados.

Tool — SQL Analytics
Amazon Athena
Execute queries SQL ad-hoc no Data Lakehouse sem provisionar infraestrutura. Retorne os resultados formatados como Markdown para o LLM construir análises e relatórios automáticos.
Tool + Resource — Metadados
AWS Glue Data Catalog
Liste databases, tabelas e schemas do Catálogo de Dados. Exponha o schema como Resource (contexto estático) e operações de DDL como Tool (ação dinâmica).
Tool — Lookups em Tempo Real
Amazon DynamoDB
Leituras por chave primária com latência sub-milissegundo. Ideal para ferramentas que precisam consultar perfis de clientes, configurações ou entidades operacionais durante o raciocínio do LLM.
Resource — Arquivos e Dados
Amazon S3
Forneça arquivos Parquet, JSON ou CSV diretamente como contexto via URI S3. O MCP Server lê e serializa o conteúdo, injetando-o no prompt sem necessidade de chamadas extras pelo Host.
Tool — OLTP Relacional
Amazon RDS / Aurora
Execute queries SQL em bancos de dados relacionais PostgreSQL ou MySQL. Use conexões via IAM Auth + SSL para autenticação segura sem segredos hardcoded no container MCP.
Tool — Data Warehouse
Amazon Redshift
Consulte petabytes de dados históricos com SQL analítico. O Redshift Data API elimina a necessidade de manter conexões persistentes, ideal para servidores MCP serverless.
ARCHITECTURE DIAGRAM — MCP AWS NATIVE SERVICES HUB
📌 Legenda & Arquitetura — AWS Native Services Hub:
  • Componentes AWS / Módulos: Amazon Bedrock (Host), ECS Fargate ou Lambda (MCP Server), Athena, AWS Glue Catalog, DynamoDB, S3, RDS PostgreSQL, Redshift, CloudWatch.
  • Integração: Bedrock envia JSON-RPC ao MCP Server; o servidor despacha Tools (Athena, Glue, DynamoDB) e Resources (S3) para os serviços AWS via IAM Task Role sem credenciais hardcoded.
  • Contexto: Padrão hub-and-spoke onde um único MCP Server centraliza o acesso a múltiplos data stores, simplificando a governança e o ciclo de vida das permissões IAM.

AWS Glue Data Catalog via MCP

Expor o catálogo de dados como ferramentas MCP permite que o LLM descubra schemas dinamicamente — sem que você precise hardcodar nomes de tabelas no prompt.

python mcp_glue_catalog.py 
from mcp.server.fastmcp import FastMCP
import boto3

mcp = FastMCP("AWS Glue Catalog MCP Server")
glue = boto3.client("glue", region_name="us-east-1")

@mcp.tool()
def list_databases() -> str:
    """Lista todos os databases disponíveis no AWS Glue Data Catalog."""
    response = glue.get_databases()
    dbs = [db["Name"] for db in response["DatabaseList"]]
    return "\n".join(f"- {d}" for d in dbs)

@mcp.tool()
def get_table_schema(database: str, table_name: str) -> str:
    """
    Retorna o schema completo de uma tabela do Glue Catalog.
    Útil para o LLM entender a estrutura antes de gerar queries SQL.

    Args:
        database: Nome do database no Glue Catalog (ex: 'analytics_db')
        table_name: Nome da tabela (ex: 'orders_parquet')
    """
    table = glue.get_table(DatabaseName=database, Name=table_name)["Table"]
    cols = table["StorageDescriptor"]["Columns"]
    parts = table.get("PartitionKeys", [])
    lines = ["## Schema da Tabela: " + table_name, ""]
    lines += ["| Coluna | Tipo |", "|--------|------|"]
    for c in cols:
        lines.append(f"| {c['Name']} | {c['Type']} |")
    for p in parts:
        lines.append(f"| {p['Name']} *(partição)* | {p['Type']} |")
    lines += ["", f"**Localização:** {table['StorageDescriptor']['Location']}"]
    return "\n".join(lines)

@mcp.resource("glue://catalog/partitions/{database}/{table}")
def get_partitions(database: str, table: str) -> str:
    """Resource: retorna as últimas 10 partições de uma tabela Glue."""
    resp = glue.get_partitions(DatabaseName=database, TableName=table, MaxResults=10)
    parts = [str(p["Values"]) for p in resp["Partitions"]]
    return f"Últimas partições de {database}.{table}:\n" + "\n".join(parts)

if __name__ == "__main__":
    mcp.run(transport="stdio")

Amazon DynamoDB via MCP

python mcp_dynamodb.py 
from mcp.server.fastmcp import FastMCP
import boto3
from boto3.dynamodb.conditions import Key
import json

mcp = FastMCP("DynamoDB Operational MCP Server")
dynamodb = boto3.resource("dynamodb", region_name="us-east-1")

@mcp.tool()
def get_customer_profile(customer_id: str) -> str:
    """
    Busca o perfil completo de um cliente pelo customer_id no DynamoDB.
    Use esta ferramenta quando o usuário mencionar um cliente ou conta específica.

    Args:
        customer_id: Identificador único do cliente (ex: 'cust-12345')
    """
    table = dynamodb.Table("customers")
    response = table.get_item(Key={"customer_id": customer_id})
    item = response.get("Item")
    if not item:
        return f"Cliente '{customer_id}' não encontrado."
    return json.dumps(item, default=str, ensure_ascii=False, indent=2)

@mcp.tool()
def query_orders_by_customer(customer_id: str, limit: int = 10) -> str:
    """
    Retorna os últimos pedidos de um cliente, ordenados por data decrescente.

    Args:
        customer_id: ID do cliente
        limit: Quantidade máxima de pedidos (default: 10, máximo: 50)
    """
    table = dynamodb.Table("orders")
    limit = min(limit, 50)
    response = table.query(
        KeyConditionExpression=Key("customer_id").eq(customer_id),
        ScanIndexForward=False,
        Limit=limit
    )
    items = response.get("Items", [])
    if not items:
        return f"Nenhum pedido encontrado para '{customer_id}'."
    lines = [f"## Últimos {len(items)} pedidos — {customer_id}", ""]
    for item in items:
        lines.append(
            f"- **{item['order_id']}** | {item.get('status','N/A')} "
            f"| R$ {float(item.get('total',0)):.2f} | {item.get('created_at','')}"
        )
    return "\n".join(lines)

if __name__ == "__main__":
    mcp.run(transport="stdio")

Bedrock Agents + Multi-Server MCP

Orquestre múltiplos MCP Servers especializados com um único Bedrock Agent como controlador central.

Em arquiteturas corporativas maduras, um único MCP Server raramente basta. A prática recomendada é criar servidores especializados por domínio (Data Engineering, Operational Data, Knowledge Base) e conectá-los a um único Bedrock Agent que age como orquestrador. O Agent decide qual servidor invocar com base na intenção do usuário.

ARCHITECTURE DIAGRAM — BEDROCK AGENTS + MULTI-SERVER MCP
📌 Legenda & Arquitetura — Multi-Server MCP com Bedrock Agent:
  • Componentes AWS / Módulos: Amazon Bedrock Agent (Claude Sonnet), MCP Server #1 (Athena + Glue), MCP Server #2 (DynamoDB + RDS), MCP Server #3 (S3 + OpenSearch).
  • Integração: O Bedrock Agent emite chamadas tool_call JSON-RPC para cada MCP Server conforme a intenção do usuário; os servidores retornam resultados que o Agent agrega antes de gerar a resposta final.
  • Contexto: Separação de concerns por domínio — cada equipe mantém seu MCP Server independentemente, mas o Agent os orquestra de forma transparente para o usuário.

Conectando Múltiplos Servidores com Strands Agent SDK

O Strands Agents SDK (open source da Amazon) permite conectar múltiplos servidores MCP em um único agente Python de forma declarativa:

python multi_server_agent.py 
from strands import Agent
from strands.tools.mcp import MCPClient
from mcp import stdio_client, StdioServerParameters

# 1. Parâmetros para cada MCP Server especializado
de_params  = StdioServerParameters(command="python", args=["mcp_glue_catalog.py"])
ops_params = StdioServerParameters(command="python", args=["mcp_dynamodb.py"])
kb_params  = StdioServerParameters(command="python", args=["mcp_knowledge_base.py"])

def run_multi_server_agent(user_query: str) -> str:
    with (
        MCPClient(lambda: stdio_client(de_params))  as de_client,
        MCPClient(lambda: stdio_client(ops_params)) as ops_client,
        MCPClient(lambda: stdio_client(kb_params))  as kb_client,
    ):
        # Combina tools dos 3 servidores numa lista única para o Agent
        all_tools = (
            de_client.list_tools_sync()
            + ops_client.list_tools_sync()
            + kb_client.list_tools_sync()
        )

        agent = Agent(
            model="us.amazon.nova-pro-v1:0",
            tools=all_tools,
            system_prompt=(
                "Você é um Data Assistant corporativo com acesso a:\n"
                "- Data Engineering (Athena, Glue Catalog)\n"
                "- Dados Operacionais (DynamoDB, RDS)\n"
                "- Base de Conhecimento (S3, OpenSearch)\n"
                "Use as ferramentas adequadas para cada pergunta."
            )
        )
        return str(agent(user_query))

# Uso
if __name__ == "__main__":
    resp = run_multi_server_agent(
        "Qual o schema da tabela de pedidos e qual foi o último "
        "pedido do cliente cust-42?"
    )
    print(resp)
💡 Dica: Namespacing de Tools

Quando múltiplos servidores expõem tools com nomes similares (ex: list_tables), prefixe os nomes com o domínio: de_list_tables, ops_get_customer. O FastMCP permite sobrescrever o nome via @mcp.tool(name="de_list_tables").

Segurança, IAM e Observabilidade

Least-privilege IAM, autenticação Cognito e logging estruturado para MCP em produção.

Um MCP Server em produção executa ações reais — consultas SQL, leituras de banco, acesso a arquivos. A superfície de ataque é proporcional às permissões IAM concedidas ao container. Aplique rigorosamente o princípio de menor privilégio e monitore cada tool invocation.

ARCHITECTURE DIAGRAM — ENTERPRISE MCP SECURITY LAYERS
📌 Legenda & Arquitetura — Security Layers do MCP Enterprise:
  • Componentes AWS / Módulos: AWS WAF, API Gateway HTTP API, Amazon Cognito (JWT Authorizer), ALB (TLS/SSE), ECS Fargate (MCP Server em subnet privada), IAM Task Role, Secrets Manager, CloudWatch Logs.
  • Integração: O cliente autentica via Cognito (obtém JWT), inclui o token no header Authorization. O API Gateway valida o JWT antes de rotear para o ALB. O ECS usa IAM Task Role para acessar Secrets Manager e serviços AWS sem credenciais estáticas.
  • Contexto: Defense-in-depth com 4 camadas: WAF (L7 filtering) → Cognito (AuthN/AuthZ) → VPC privada (network isolation) → IAM least-privilege (data access control).

Logging Estruturado com CloudWatch

Instrumente cada tool invocation com logs JSON estruturados para rastrear latência, erros e custo por chamada em um dashboard CloudWatch Logs Insights.

python mcp_observability.py 
from mcp.server.fastmcp import FastMCP
import boto3, json, time, logging, sys

logging.basicConfig(stream=sys.stderr, level=logging.INFO, format='%(message)s')
logger = logging.getLogger("mcp-server")

mcp = FastMCP("Observed MCP Server")
athena = boto3.client("athena", region_name="us-east-1")

def _log(tool: str, params: dict, chars: int, ms: float, err: str = None):
    rec = {"service": "mcp-server", "tool": tool, "params": params,
           "result_chars": chars, "elapsed_ms": round(ms, 2)}
    if err:
        rec["error"] = err
    logger.info(json.dumps(rec, ensure_ascii=False))

@mcp.tool()
def query_athena_observed(database: str, query: str) -> str:
    """Executa query Athena com telemetria — registra latência e erros no CloudWatch."""
    t0 = time.time()
    err = None
    result = ""
    try:
        resp = athena.start_query_execution(
            QueryString=query,
            QueryExecutionContext={"Database": database},
            WorkGroup="mcp-workgroup"
        )
        qid = resp["QueryExecutionId"]
        for _ in range(30):
            state = athena.get_query_execution(QueryExecutionId=qid)
            state = state["QueryExecution"]["Status"]["State"]
            if state in ("SUCCEEDED", "FAILED", "CANCELLED"):
                break
            time.sleep(1)
        if state != "SUCCEEDED":
            raise RuntimeError(f"Query falhou: {state}")
        rows = athena.get_query_results(QueryExecutionId=qid)["ResultSet"]["Rows"]
        result = "\n".join(
            " | ".join(c.get("VarCharValue", "") for c in r["Data"])
            for r in rows[:51]
        )
    except Exception as e:
        err = str(e)
        result = f"Erro: {err}"
    finally:
        _log("query_athena", {"database": database}, len(result), (time.time()-t0)*1000, err)
    return result

if __name__ == "__main__":
    mcp.run(transport="sse", host="0.0.0.0", port=8080)
