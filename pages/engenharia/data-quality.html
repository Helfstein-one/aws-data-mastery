Data Quality & Business Quality

Governança proativa, validação de regras de negócios, AWS Glue DQ, Amazon Deequ e Circuit Breakers Analíticos.

01

Conceitos Técnicos de Data Quality

Os pilares da confiabilidade dos dados e as métricas fundamentais de observabilidade.

A qualidade de dados (DQ) não é um projeto pontual, mas uma disciplina contínua de engenharia e governança. Sem DQ, um Data Lake se torna um pântano (Data Swamp) de informações não confiáveis, quebrando pipelines de Machine Learning e destruindo a confiança dos executivos nos dashboards financeiros.

Dimensões Fundamentais de Qualidade

Dimensão Descrição Exemplo Técnico (AWS Glue DQDL)
Completude (Completeness) Garante que atributos críticos não sejam nulos ou vazios. Completeness "cpf" > 0.99
Acurácia (Accuracy) O dado reflete a realidade do mundo (sintática e semanticamente). ColumnValues "idade" > 0 AND < 120
Unicidade (Uniqueness) Identificação e tratamento de registros duplicados absolutos ou parciais. IsPrimaryKey "transaction_id"
Tempestividade (Timeliness) O dado está disponível no SLA acordado (Data Freshness). ColumnValues "data_proc" > (now() - 2h)
END-TO-END DATA QUALITY PLATFORM
02

Business Quality (Extensivo)

Alinhamento de regras técnicas com o valor real e impacto financeiro nos domínios de negócio.

Enquanto Data Quality foca em garantir que a coluna "Salário" seja do tipo FLOAT e não seja NULL, Business Quality foca em garantir que o valor do "Salário" faça sentido no contexto das regras da empresa. Se um sistema de RH calcular o salário de um estagiário como R$ 500.000, a Qualidade de Dados técnica dirá que está perfeito (é um float não nulo), mas a Qualidade de Negócios acionará um alerta crítico.

Traduzindo Requisitos de Negócios para Código (Deequ/DQDL)

Engenheiros de Dados Seniores devem trabalhar lado a lado com os Data Product Owners e SMEs para mapear as complexidades do domínio. Veja exemplos de mercado:

Domínio Regra de Negócio (Business Quality) Implementação Técnica (AWS Glue / Deequ)
Fintech (Cartões) "Clientes na categoria 'Black' não podem ter limite de crédito menor que R$ 10.000." CustomSql "SELECT count(*) FROM table WHERE tier='Black' AND limite < 10000" == 0
E-commerce "Uma compra não pode ter data de entrega anterior à data de processamento do pedido." ColumnValues "data_entrega" >= "data_pedido"
Logística "A geolocalização do caminhão não pode indicar um salto maior que 500km em 1 hora." Validação complexa via PySpark Window Functions + UDFs no EMR.

Dica de Arquiteto: Isole as regras técnicas (nulos, duplicatas) na camada Bronze/Raw (usando DQDL). Regras de Business Quality (que dependem de cruzamento de tabelas e lógica de negócio) devem ser validadas na camada Silver/Gold ou no pipeline de transformação (dbt/Spark).

03

Case Prático: DQDL Circuit Breaker

Isolando dados podres antes que contaminem o Data Lake financeiro.

Cenário: Um banco recebe streams de transações de adquirência via Kinesis. Ocasionalmente, o parceiro envia lotes inteiros com o campo valor_transacao mascarado ou corrompido. Se isso entrar na camada consumível, os relatórios de fechamento de caixa apresentarão rombos milionários.

Solução: Implementar um padrão Circuit Breaker usando AWS Glue Streaming e Data Quality. O stream é processado em micro-batches. Antes da gravação (Sink), a API de Data Quality do Glue avalia o batch. Se o Score de Qualidade cair abaixo de 95%, o batch inteiro é roteado para uma Dead Letter Queue (S3 Quarantine) e não entra no Lake principal.

CIRCUIT BREAKER ARCHITECTURE

python glue_circuit_breaker.py

from awsglue.gluedq.transforms import EvaluateDataQuality

# Regras de DQDL
ruleset = """
Rules = [
    IsComplete "transaction_id",
    IsComplete "valor_transacao",
    ColumnValues "valor_transacao" > 0,
    ColumnLength "currency" == 3
]
"""

# Avaliação do DataFrame em memória (DynamicFrame)
dq_results = EvaluateDataQuality().apply(
    frame = dynamic_frame,
    ruleset = ruleset,
    publishing_options = {"dataQualityEvaluationContext": "Streaming_Tx", "enableDataQualityCloudWatchMetrics": True}
)

# Roteamento baseado no resultado
if dq_results.get_score() >= 0.95:
    write_to_s3_trusted(dynamic_frame)
else:
    write_to_s3_quarantine(dynamic_frame)
    trigger_sns_alert("Batch Reprovado no Circuit Breaker de DQ")

Playbook de Crise: Schema Drift Silencioso

Como resolver incidentes onde a origem muda o tipo de dado sem avisar.

Incidente P1: O time de backend da aplicação principal alterou o campo id_cliente de INT para UUID (STRING). Os pipelines de ingestão quebram com erros de casting, ou pior, sistemas baseados em schema-on-read (Athena) começam a retornar silenciosamente NULL para todos os novos IDs de cliente.

SCHEMA DRIFT CRISIS MITIGATION

Plano de Mitigação (RCA-M)

  • Detecção (T0 + 5m): Alarme do AWS Glue Schema Registry dispara via EventBridge ao detectar versão incompatível (Backward Incompatible).
  • Contenção (T0 + 15m): O pipeline de ingestão pausa automaticamente. Dados são retidos em buffers (Kinesis/Kafka) que possuem 7 dias de retenção.
  • Resolução (T0 + 40m): Cria-se uma nova tabela no Lakehouse (ex: clientes_v2) ou utiliza-se recursos de Schema Evolution do Apache Iceberg para promover a coluna para STRING.
  • Pós-Mortem: Implementar Data Contracts obrigatórios na borda da API para que quebras de schema sejam bloqueadas no CI/CD do produtor, e não na Engenharia de Dados.

Simulador de Entrevistas: Data Quality

Teste seu conhecimento com perguntas reais de design system.

Sênior / Especialista

Como você gerenciaria regras de Data Quality para 5.000 tabelas no Data Lake sem hardcodar os scripts?

Cenário: Sua empresa possui milhares de tabelas. Criar um job do AWS Glue DQ para cada tabela é insustentável. Como arquitetar uma validação escalável guiada por metadados?

Gabarito Arquitetural:
  • Construir um Data Quality Framework Baseado em Metadados.
  • Criar uma tabela de configuração no DynamoDB onde cada item é o nome da tabela e o JSON contendo as regras DQDL ou Deequ específicas para ela.
  • Ter um único Job Glue genérico parametrizado. O Job lê o nome da tabela, busca no DynamoDB as regras associadas, converte para o formato do avaliador e executa a validação dinâmica.
  • Integração com AWS Step Functions para orquestrar a varredura noturna em milhares de tabelas em paralelo (Map State).
