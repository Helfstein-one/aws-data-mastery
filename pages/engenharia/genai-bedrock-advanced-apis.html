Converse API & Tool Use (Function Calling)

API unificada multi-modelo com suporte nativo a ferramentas estruturadas — sem parsing manual de JSON.

A Converse API é a forma moderna de interagir com o Amazon Bedrock. Diferente da InvokeModel, ela: (1) funciona com qualquer modelo suportado sem mudar o código, (2) mantém histórico de conversa (multi-turn), e (3) suporta Tool Use nativo — o modelo decide quando chamar uma função e estrutura os argumentos em JSON garantido.

Portabilidade
Multi-Model Unificado
O mesmo código funciona com Claude 3.5 Sonnet, Llama 3, Mistral, Amazon Nova — sem adaptadores. Troca de modelo = troca do modelId string. Facilita A/B testing de modelos.
Agentes
Tool Use / Function Calling
Defina ferramentas com schema JSON. O modelo decide quando chamá-las, retorna argumentos estruturados. Você executa a função e devolve o resultado — o modelo continua a conversa com o dado real.
Conversa
Multi-Turn Nativo
Passe o histórico completo de mensagens (messages array). O modelo mantém contexto entre turnos sem que você precise gerenciar janela de contexto manualmente.

Exemplo Completo: Agente de Dados com Tool Use

import boto3
import json

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

# Definição das ferramentas disponíveis para o modelo
tools = [
    {
        "toolSpec": {
            "name": "query_athena",
            "description": "Executa uma query SQL no Amazon Athena e retorna os resultados. Use para responder perguntas sobre dados de negócio.",
            "inputSchema": {
                "json": {
                    "type": "object",
                    "properties": {
                        "sql": {
                            "type": "string",
                            "description": "Query SQL válida para o Athena. Sempre use LIMIT para evitar queries caras."
                        },
                        "database": {
                            "type": "string",
                            "description": "Nome do database no Glue Catalog",
                            "enum": ["vendas_db", "financeiro_db", "logistica_db"]
                        }
                    },
                    "required": ["sql", "database"]
                }
            }
        }
    },
    {
        "toolSpec": {
            "name": "get_metric",
            "description": "Busca uma métrica do CloudWatch para uma janela de tempo.",
            "inputSchema": {
                "json": {
                    "type": "object",
                    "properties": {
                        "metric_name": {"type": "string"},
                        "namespace": {"type": "string"},
                        "period_hours": {"type": "integer"}
                    },
                    "required": ["metric_name", "namespace"]
                }
            }
        }
    }
]

def call_tool(tool_name: str, tool_input: dict) -> str:
    """Executa a ferramenta e retorna o resultado como string."""
    if tool_name == "query_athena":
        # Aqui você executa a query real no Athena
        return json.dumps({"rows": [{"regiao": "Sul", "receita": 450000}], "count": 1})
    elif tool_name == "get_metric":
        return json.dumps({"average": 245.3, "unit": "Milliseconds"})
    return json.dumps({"error": "Ferramenta não encontrada"})

def agent_loop(user_question: str, model_id: str = "anthropic.claude-3-5-sonnet-20241022-v2:0"):
    """Loop de agentic tool use com Converse API."""
    messages = [{"role": "user", "content": [{"text": user_question}]}]

    while True:
        response = bedrock.converse(
            modelId=model_id,
            messages=messages,
            toolConfig={"tools": tools},
            system=[{"text": "Você é um assistente de análise de dados. Use as ferramentas disponíveis para responder perguntas com dados reais."}],
            inferenceConfig={"maxTokens": 2048, "temperature": 0.1}
        )

        stop_reason = response["stopReason"]
        assistant_message = response["output"]["message"]
        messages.append(assistant_message)

        if stop_reason == "end_turn":
            # Resposta final sem tool use
            return assistant_message["content"][0]["text"]

        elif stop_reason == "tool_use":
            # Processar chamadas de ferramenta
            tool_results = []
            for block in assistant_message["content"]:
                if block.get("type") == "toolUse":
                    result = call_tool(block["name"], block["input"])
                    tool_results.append({
                        "type": "toolResult",
                        "toolUseId": block["toolUseId"],
                        "content": [{"text": result}]
                    })

            messages.append({"role": "user", "content": tool_results})
        else:
            break

    return "Conversa encerrada sem resposta."

# Uso
answer = agent_loop("Qual foi a receita total da região Sul no último mês?")
print(answer)

Prompt Caching — Redução de Custo em até 90%

Cache de prefixos de prompt para contextos grandes e repetitivos.

Em sistemas RAG ou com documentos longos, o mesmo contexto (instruções do sistema + documentos de referência) é enviado repetidamente a cada turno de conversa. O Prompt Caching armazena o prefixo do prompt processado — tokens subsequentes que acertam o cache custam ~90% menos e chegam mais rápido:

import boto3

bedrock = boto3.client("bedrock-runtime")

SYSTEM_PROMPT = """Você é um especialista em análise de dados da empresa XYZ.
[... 2000 tokens de instruções detalhadas ...]"""

REFERENCE_DOCS = """
[Documento 1: Política de Preços — 3000 tokens]
[Documento 2: Catálogo de Produtos — 2500 tokens]
[Documento 3: Histórico de Campanhas — 2500 tokens]
"""

def chat_with_cache(user_question: str, conversation_history: list):
    """Chat com prompt caching no prefixo."""
    response = bedrock.converse(
        modelId="anthropic.claude-3-5-sonnet-20241022-v2:0",
        system=[
            {
                "text": SYSTEM_PROMPT + REFERENCE_DOCS,
                "cacheControl": {"type": "ephemeral"}  # marca para cache
            }
        ],
        messages=conversation_history + [
            {"role": "user", "content": [{"text": user_question}]}
        ],
        inferenceConfig={"maxTokens": 1024}
    )

    # Verificar uso do cache nas métricas
    usage = response["usage"]
    cache_read    = usage.get("cacheReadInputTokens", 0)
    cache_written = usage.get("cacheWriteInputTokens", 0)
    regular_input = usage.get("inputTokens", 0)

    print(f"Cache Read: {cache_read} tokens (0.1× custo)")
    print(f"Cache Write: {cache_written} tokens (1.25× custo)")
    print(f"Input normal: {regular_input} tokens (1× custo)")

    return response["output"]["message"]["content"][0]["text"]

# Primeira chamada: escreve o cache
r1 = chat_with_cache("Qual o desconto máximo para clientes Gold?", [])

# Segunda chamada: lê do cache (90% mais barato)
r2 = chat_with_cache("E para clientes Platinum?", [
    {"role": "user", "content": [{"text": "Qual o desconto máximo para clientes Gold?"}]},
    {"role": "assistant", "content": [{"text": r1}]}
])

Batch Inference — Processamento Assíncrono em Massa

Classificação, extração e geração em milhares de documentos com até 50% de desconto.

A Batch Inference (anteriormente chamada Model Invocation Job) é ideal quando você tem milhares de itens para processar (classificar reviews, extrair entidades de contratos, gerar resumos em massa) e pode tolerar latência de horas — o custo é até 50% menor que chamadas síncronas:

import boto3
import json

bedrock = boto3.client("bedrock")

# Preparar arquivo de input (JSONL — um request por linha)
# Salvar em S3: s3://meu-bucket/batch-input/requests.jsonl
# Formato: {"recordId": "001", "modelInput": {"messages": [...], "max_tokens": 200}}

batch_job = bedrock.create_model_invocation_job(
    jobName="classifica-reviews-2025-01",
    modelId="anthropic.claude-3-haiku-20240307-v1:0",
    roleArn="arn:aws:iam::123456789:role/BedrockBatchRole",
    inputDataConfig={
        "s3InputDataConfig": {
            "s3Uri": "s3://meu-bucket/batch-input/requests.jsonl",
            "s3InputFormat": "JSONLines"
        }
    },
    outputDataConfig={
        "s3OutputDataConfig": {
            "s3Uri": "s3://meu-bucket/batch-output/",
            "s3EncryptionKeyId": "arn:aws:kms:us-east-1:123:key/abc-123"
        }
    },
    # Timeout máximo do job (opcional)
    timeoutDurationInHours=24
)

job_arn = batch_job["jobArn"]
print(f"Job iniciado: {job_arn}")

# Monitorar status
import time
while True:
    status = bedrock.get_model_invocation_job(jobIdentifier=job_arn)
    state = status["status"]
    print(f"Status: {state}")
    if state in ["Completed", "Failed", "Stopped"]:
        break
    time.sleep(60)

# Output é JSONL em S3: um resultado por linha
# Processar resultados
s3 = boto3.client("s3")
# Download e parse do arquivo de output...
💡 Custo-Benefício: Quando Usar Batch
Use Batch quando: latência pode ser de horas, volume acima de 1000 itens, tarefas repetitivas (classificação, extração, sumarização). Custo até 50% menor. Não use quando: usuário aguarda resposta em tempo real, latência < 10s é requisito, ou o volume é pequeno (overhead de setup não compensa).

Cross-Region Inference Profiles

Roteamento automático entre regiões para throughput maior e latência otimizada.

Inference Profiles são configurações gerenciadas que roteiam requests entre múltiplas regiões AWS automaticamente. Útil para: (1) aumentar throughput além dos limites de uma região, (2) reduzir latência escolhendo a região mais próxima, (3) resiliência contra falhas regionais:

import boto3

bedrock = boto3.client("bedrock-runtime", region_name="us-east-1")

# System-defined profile: inclui us-east-1, us-west-2, eu-west-1
# O ARN tem o prefixo "us." que indica roteamento cross-region
CROSS_REGION_PROFILE_ARN = (
    "arn:aws:bedrock:us-east-1::foundation-model/"
    "anthropic.claude-3-5-sonnet-20241022-v2:0"
    # Na prática, use o ARN do Inference Profile listado no console
)

response = bedrock.converse(
    # Usar o Inference Profile ID (não o modelId direto)
    modelId="us.anthropic.claude-3-5-sonnet-20241022-v2:0",
    messages=[{
        "role": "user",
        "content": [{"text": "Resuma este contrato em 3 pontos principais..."}]
    }],
    inferenceConfig={"maxTokens": 500}
)

# A resposta inclui a região que efetivamente processou o request
print(response["output"]["message"]["content"][0]["text"])

# Listar profiles disponíveis
bedrock_client = boto3.client("bedrock")
profiles = bedrock_client.list_inference_profiles(typeEquals="SYSTEM_DEFINED")
for p in profiles["inferenceProfileSummaries"]:
    print(f"{p['inferenceProfileName']}: {p['inferenceProfileId']}")
