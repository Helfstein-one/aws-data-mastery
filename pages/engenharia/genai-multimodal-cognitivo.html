Multimodal & ETL Cognitivo

1. A Morte do OCR Clássico

Até 2023, Engenheiros de Dados usavam ferramentas de OCR clássicas (como AWS Textract ou Tesseract) para ler faturas e documentos. O problema? Se o layout da fatura mudasse 2 milímetros para a direita, as expressões regulares (Regex) e mapeamentos de coordenadas X/Y quebravam inteiros pipelines de dados.

Com os Modelos Multimodais (Vision) como o Claude 3.5 Sonnet, GPT-4o e LLaMA 3.2 Vision, podemos passar os pixels brutos do documento direto para o modelo e pedir: "Extraia o valor total, os impostos e o nome do vendedor em JSON válido." Ele entende a semântica visual, não importando a formatação.

2. Arquitetura de Pipeline Multimodal

Na AWS, o processamento de imagens e documentos pode ser orquestrado usando Step Functions, Lambda e Amazon Bedrock.

📥

1. Ingestão (Amazon S3)

O cliente envia PDFs escaneados, contratos manchados ou fotos de recibos (JPG/PNG) para um bucket S3 RAW. Isso dispara um evento (S3 Event Notification).

🧠

2. Processamento Cognitivo

Uma Lambda intercepta o arquivo, converte PDFs pesados em imagens e os envia via API (Boto3) para o Amazon Bedrock (Claude 3.5 Sonnet).

📊

3. Carga Analítica

O LLM devolve um JSON puro extraído da imagem. Esse JSON é validado, catalogado no AWS Glue e inserido em uma tabela estruturada do Amazon Athena/Iceberg.

3. ETL Cognitivo com Python & Boto3

Veja como é simples ler uma imagem de recibo e forçar o LLM a cuspir um dado estruturado.

Extração Visual em JSON (Claude via Boto3) 
import boto3
import json

bedrock = boto3.client('bedrock-runtime')

def extrair_dados_fatura(imagem_bytes):
    # Prompt forçando a saída em JSON estruturado
    prompt = """Você é um especialista em faturas. Olhe para a imagem e retorne APENAS um JSON válido com os seguintes campos:
    - razao_social
    - cnpj
    - valor_total_impostos
    - data_vencimento
    """
    
    body = json.dumps({
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 1000,
        "messages": [
            {
                "role": "user",
                "content": [
                    {
                        "type": "image",
                        "source": {
                            "type": "base64",
                            "media_type": "image/jpeg",
                            "data": imagem_bytes
                        }
                    },
                    {"type": "text", "text": prompt}
                ]
            }
        ]
    })
    
    response = bedrock.invoke_model(
        modelId="anthropic.claude-3-5-sonnet-20240620-v1:0",
        body=body
    )
    return json.loads(response['body'].read())
⚡ Dica FinOps: Processamento de Imagens gasta milhares de Tokens. Se você tiver 1 milhão de documentos/dia, considere usar técnicas híbridas: Rode o AWS Textract primeiro (barato), passe o texto bruto para um LLM leve como LLaMA 3 8B (grátis/barato) para estruturar os dados.

4. Áudio e Multimodalidade Futura

Engenheiros de Dados também precisam lidar com Call Centers. Hoje, a stack ideal na AWS para extrair sentimentos, intenções de cancelamento de churn e temas de chamadas (ligações gravadas) é usar o Amazon Transcribe para converter o Áudio em Texto (Speech-to-Text), e então plugar esse log de texto massivo em um pipeline RAG ou diretamente no Bedrock para Analytics.
