Engenharia de Dados AWS

Arquitetura Kafka Event Streaming & Dual Feature Store (AWS 2026)

Para viabilizar decisões em milissegundos sem sobrecarregar bancos OLTP transacionais, a arquitetura moderna de onboarding utiliza barramentos de eventos no Apache Kafka (Amazon MSK) e uma dual Feature Store de baixa latência (DynamoDB Online + S3 Iceberg Offline).

Abordagem 2: Topologia de Infraestrutura AWS Cloud — VPC Multi-AZ, Subnets, Security Groups & Governança Lake Formation
Explicação da Topologia de Infraestrutura Cloud (Abordagem 2):
  • Isolamento de Redes (VPC Multi-AZ): As subnets públicas abrigam apenas o API Gateway e AWS AppSync para entrada de tráfego de borda. Toda a camada de mensageria (Amazon MSK 3-AZ), processamento (Flink) e motor de crédito roda estritamente isolada em Subnets Privadas sem IP público.
  • Segurança & Conexão BACEN: A comunicação com a Rede do Sistema Financeiro Nacional (RSFN do Banco Central) é realizada via AWS DirectConnect dedicado. O tráfego para buckets S3 não trafega na internet pública, operando via VPC Endpoints (PrivateLink).
  • Governança de Dados LGPD: O AWS Lake Formation gerencia as permissões granulares em nível de célula (Cell-Level Security / Data Filtering) nos buckets S3 Iceberg, enquanto todas as chaves e tokens de PII são encriptados com AWS KMS.
Consistência e Resiliência em Pipeline de Onboarding:

A arquitetura garante resiliência total a picos de tráfego. Em caso de indisponibilidade momentânea nos bureaus externos (ex: SCR BACEN), o Apache Flink retém o estado da proposta em RocksDB com retenção de janela e dispara re-tentativas com backoff exponencial via Amazon MSK DLQ (Dead Letter Queue).
