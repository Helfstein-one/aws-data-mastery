Aplicações Práticas (Bedrock API)

Como automatizar tarefas entediantes do Engenheiro de Dados utilizando LLMs.

Além de criarmos Chatbots para os usuários finais, a GenAI brilha intensamente em produtividade interna para os times de dados. Nós podemos automatizar tarefas de governança, documentação e qualidade injetando a inteligência do Claude diretamente nos nossos scripts Python de pipeline.

Caso de Uso 1: Autocatalogação e Enriquecimento de Metadados (Glue Data Catalog)

Este script utiliza a biblioteca `boto3` para conectar ao Bedrock, ler a estrutura física de uma tabela desconhecida e pedir para o Claude 3.5 gerar descrições ricas de negócios para cada coluna, bem como apontar se há dados sensíveis (PII) para mascaramento automático (LGPD).

import boto3
import json

bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')

def auto_catalog_schema(table_name, schema_fields):
    """Analisa o schema e retorna um mapa JSON com descrições e flags de PII."""
    prompt = f"""
    Você é um especialista em governança de dados corporativos. Sua tarefa é analisar o schema da tabela '{table_name}' fornecida abaixo e gerar descrições técnicas claras para cada coluna, além de classificar se a coluna contém dados pessoais sensíveis (PII).

    Retorne a resposta estritamente no formato JSON estruturado, sem comentários explicativos adicionais.

    <schema>
    {json.dumps(schema_fields, indent=2)}
    </schema>

    Exemplo de formato de saída esperado:
    {{
      "colunas": [
        {{
          "nome": "id_usuario",
          "descricao": "Identificador único sequencial do usuário cadastrado na plataforma",
          "contem_pii": false
        }},
        {{
          "nome": "num_cpf",
          "descricao": "Número do registro nacional de Cadastro de Pessoas Físicas do cliente",
          "contem_pii": true
        }}
      ]
    }}
    """
    
    payload = {
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 1000,
        "temperature": 0.0,  # Temperatura 0 para respostas puramente analíticas e determinísticas
        "messages": [
            {"role": "user", "content": prompt}
        ]
    }
    
    response = bedrock.invoke_model(
        modelId="anthropic.claude-3-5-sonnet-20240620-v1:0",
        contentType="application/json",
        accept="application/json",
        body=json.dumps(payload)
    )
    
    result = json.loads(response['body'].read())
    return json.loads(result['content'][0]['text'])

Caso de Uso 2: Geração Autônoma de Regras de Qualidade (AWS Glue DQDL)

Um desafio comum na ingestão (Fase Bronze) é descobrir as regras de integridade sem conhecer o dado a fundo. Podemos pedir para o Claude analisar o schema e construir blocos lógicos usando o DQDL (Data Quality Definition Language) nativo da AWS, que pode ser integrado em jobs do Glue ou Amazon Deequ (Spark).

def generate_dqdl_rules(table_name, schema_fields):
    """Gera bloco declarativo DQDL com base no perfil de colunas analisado."""
    prompt = f"""
    Você é um Engenheiro de Qualidade de Dados sênior. Sua tarefa é analisar o schema fornecido e gerar regras de qualidade de dados escritas em DQDL (Data Quality Definition Language) do AWS Glue.

    <schema>
    {json.dumps(schema_fields, indent=2)}
    </schema>

    Gere regras validando nulidade (IsComplete), consistência de tipos numéricos não negativos e checagens lógicas. Retorne estritamente o bloco de regras DQDL.

    Exemplo de saída esperada:
    Rules = [
        IsComplete "id_cliente",
        ColumnValues "valor_total" >= 0,
        IsComplete "email"
    ]
    """
    
    payload = {
        "anthropic_version": "bedrock-2023-05-31",
        "max_tokens": 800,
        "temperature": 0.1,
        "messages": [
            {"role": "user", "content": prompt}
        ]
    }
    
    response = bedrock.invoke_model(
        modelId="anthropic.claude-3-5-sonnet-20240620-v1:0",
        contentType="application/json",
        accept="application/json",
        body=json.dumps(payload)
    )
    
    result = json.loads(response['body'].read())
    return result['content'][0]['text']

Text-to-SQL: Analistas em Linguagem Natural

Um pipeline completo que converte perguntas de negócio em SQL executado no Athena — zero conhecimento de SQL exigido do usuário.

O padrão Text-to-SQL com LLM é um dos casos de uso de maior ROI na Engenharia de Dados: analistas de negócio passam a consultar o Data Lake diretamente, sem depender de tickets para a equipe de dados. A arquitetura é: pergunta → Bedrock gera SQL → Athena executa → resultado formatado pelo LLM.

Schema Injection
Context do Glue Catalog
O schema das tabelas é injetado automaticamente no prompt via boto3 get_table(). O LLM conhece colunas, tipos e partições sem treinamento adicional.
Few-Shot
Exemplos de Negócio
3-5 exemplos de pergunta → SQL específicos do seu domínio reduzem erros em 70%. Use perguntas que o próprio time faria: "total de vendas por canal este mês".
Validação
Guard Rails de SQL
Bloqueie operações destrutivas (DROP, DELETE, INSERT) via regex antes de enviar ao Athena. Limite resultados com LIMIT automático para evitar scans caros.
import boto3, json, re, time

bedrock  = boto3.client('bedrock-runtime', region_name='us-east-1')
glue     = boto3.client('glue',           region_name='us-east-1')
athena   = boto3.client('athena',         region_name='us-east-1')

def get_schema_context(database: str, table_names: list[str]) -> str:
    """Busca schema do Glue Catalog e formata para o prompt."""
    lines = []
    for t in table_names:
        tbl = glue.get_table(DatabaseName=database, Name=t)['Table']
        cols = [f"{c['Name']} ({c['Type']})" for c in tbl['StorageDescriptor']['Columns']]
        parts = [f"{p['Name']} ({p['Type']})" for p in tbl.get('PartitionKeys', [])]
        lines.append(f"Tabela: {database}.{t}\n  Colunas: {', '.join(cols)}\n  Partições: {', '.join(parts) or 'nenhuma'}")
    return "\n\n".join(lines)

def nl_to_sql_athena(pergunta: str, database: str = 'sales_gold') -> dict:
    schema = get_schema_context(database, ['fato_vendas', 'dim_produto', 'dim_regiao'])
    prompt = f"""Você é um engenheiro de dados especialista em Amazon Athena (SQL Presto).
Converta a pergunta em SQL executável. NUNCA use DELETE/DROP/INSERT/UPDATE.
Adicione LIMIT 5000 se não houver agregação.

<schema>
{schema}
</schema>

<exemplo>
<pergunta>Total de vendas por produto neste mês</pergunta>
<sql>SELECT p.nome_produto, SUM(v.valor_venda) AS total
FROM sales_gold.fato_vendas v JOIN sales_gold.dim_produto p USING(produto_id)
WHERE v.dt_venda >= DATE_TRUNC('month', CURRENT_DATE)
GROUP BY 1 ORDER BY 2 DESC LIMIT 50</sql>
</exemplo>

<pergunta>{pergunta}</pergunta>
Responda APENAS com <sql>...</sql>."""

    resp = bedrock.converse(
        modelId='anthropic.claude-3-5-haiku-20241022-v1:0',
        messages=[{"role": "user", "content": [{"text": prompt}]}],
        inferenceConfig={"temperature": 0.0, "maxTokens": 600}
    )
    raw_sql = re.search(r'<sql>(.*?)</sql>', resp['output']['message']['content'][0]['text'], re.DOTALL)
    sql = raw_sql.group(1).strip() if raw_sql else ""

    # Guard: bloqueia operações destrutivas
    if re.search(r'\b(DELETE|DROP|INSERT|UPDATE|TRUNCATE)\b', sql, re.IGNORECASE):
        raise ValueError("SQL destrutivo bloqueado pelo guard rail.")

    # Executa no Athena
    execution = athena.start_query_execution(
        QueryString=sql,
        QueryExecutionContext={'Database': database},
        ResultConfiguration={'OutputLocation': 's3://my-athena-results/text-to-sql/'}
    )
    exec_id = execution['QueryExecutionId']

    # Poll até concluir (produção: use Step Functions ou EventBridge)
    while True:
        state = athena.get_query_execution(QueryExecutionId=exec_id)['QueryExecution']['Status']['State']
        if state in ('SUCCEEDED', 'FAILED', 'CANCELLED'): break
        time.sleep(1)

    results = athena.get_query_results(QueryExecutionId=exec_id)['ResultSet']['Rows']
    return {"sql_gerado": sql, "rows": results[:20], "status": state}

# Uso
resultado = nl_to_sql_athena("Qual foi o produto mais vendido na região Sul em junho?")
print(resultado['sql_gerado'])

ETL Cognitivo — Glue + Bedrock para Schema Drift

Usando LLMs para detectar e sugerir correções automáticas quando schemas evoluem inesperadamente no pipeline.

Schema drift é um dos maiores causadores de falha silenciosa em pipelines: uma coluna é renomeada pelo sistema de origem, o job do Glue continua rodando, mas gera NULLs em vez de dados. Com um LLM no loop, o pipeline detecta a divergência e sugere o mapeamento correto antes de gravar na camada Gold.

Detecção
Schema Diff Automático
Compare o schema esperado (catalogado no Glue) com o schema real dos dados recebidos. Qualquer divergência de nome, tipo ou cardinalidade alimenta o prompt de análise.
Sugestão
Mapeamento Semântico
O LLM analisa semanticamente: "customer_id" e "id_cliente" provavelmente são a mesma coisa. Ele sugere um mapeamento JSON que o job Glue aplica como transformação de coluna.
Ação
Auto-Heal ou Alerta
Se a confiança do mapeamento for alta (>0.9), aplica automaticamente. Se baixa, aciona SNS com o contexto completo para revisão humana — Human-in-the-loop controlado.
import boto3, json
from pyspark.sql import SparkSession
from awsglue.context import GlueContext

spark = SparkSession.builder.getOrCreate()
gc = GlueContext(spark.sparkContext)
bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')
sns = boto3.client('sns', region_name='us-east-1')

EXPECTED_SCHEMA = {
    "customer_id": "string", "order_date": "date",
    "product_sku": "string", "revenue": "double"
}

def detect_and_heal_schema_drift(df, table_name: str):
    actual_schema = {f.name: str(f.dataType) for f in df.schema.fields}
    missing = [c for c in EXPECTED_SCHEMA if c not in actual_schema]
    extra   = [c for c in actual_schema   if c not in EXPECTED_SCHEMA]

    if not (missing or extra):
        return df  # Schema OK, sem drift

    # Pede ao LLM para sugerir mapeamento semântico
    prompt = f"""Analise o schema drift da tabela '{table_name}'.
Schema esperado: {json.dumps(EXPECTED_SCHEMA)}
Schema recebido: {json.dumps(actual_schema)}
Colunas faltando: {missing}
Colunas extras:   {extra}

Sugira um mapeamento JSON no formato:
{{"mappings": [{{"de": "nome_recebido", "para": "nome_esperado", "confianca": 0.95, "motivo": "..."}}, ...], "acao_recomendada": "auto_heal|alerta_humano"}}
Responda apenas com JSON válido."""

    resp = bedrock.converse(
        modelId='anthropic.claude-3-5-haiku-20241022-v1:0',
        messages=[{"role": "user", "content": [{"text": prompt}]}],
        inferenceConfig={"temperature": 0.0, "maxTokens": 400}
    )
    suggestion = json.loads(resp['output']['message']['content'][0]['text'])

    if suggestion['acao_recomendada'] == 'auto_heal':
        # Aplica renomeações sugeridas com alta confiança
        for m in suggestion['mappings']:
            if m['confianca'] >= 0.9:
                df = df.withColumnRenamed(m['de'], m['para'])
        return df
    else:
        # Publica alerta no SNS com contexto completo para revisão humana
        sns.publish(
            TopicArn='arn:aws:sns:us-east-1:123456789012:data-quality-alerts',
            Message=json.dumps({"tabela": table_name, "sugestao": suggestion}),
            Subject=f"Schema Drift detectado: {table_name}"
        )
        raise RuntimeError(f"Schema drift requer revisão humana: {missing}")

# No job Glue
df_raw = gc.create_dynamic_frame.from_catalog(database="raw", table_name="orders").toDF()
df_healed = detect_and_heal_schema_drift(df_raw, "orders")
df_healed.write.format("iceberg").mode("append").save("sales_gold.orders")

AI-Assisted Data Quality — Detecção e Diagnóstico

Usando Bedrock para interpretar métricas de qualidade e gerar diagnósticos em linguagem natural para o time de negócio.

O AWS Glue Data Quality e o Amazon Deequ geram scores de qualidade numéricos, mas o stakeholder de negócio não sabe o que fazer com "Completeness score: 0.73". Um LLM no loop transforma esse número em: "31.1% do campo CPF está vazio na tabela de clientes. Isso impacta relatórios de LGPD e pode indicar falha na integração com o sistema X."

Glue DQ
Scores Numéricos
O Glue Data Quality avalia regras DQDL (IsComplete, ColumnValues, Uniqueness) e retorna scores 0-1 por regra. Esses resultados ficam disponíveis via CloudWatch e S3.
Bedrock
Diagnóstico em NL
O LLM recebe os scores + contexto da tabela e gera um relatório em português explicando o impacto de negócio, causas prováveis e ações recomendadas.
SNS + Lambda
Alertas Inteligentes
Em vez de alertas técnicos ("completeness < 0.8"), o time recebe: "Atenção: 27% dos pedidos do dia não têm CEP preenchido. Verificar integração com app mobile."
import boto3, json

bedrock = boto3.client('bedrock-runtime', region_name='us-east-1')

def generate_dq_narrative(dq_results: dict, table_context: str) -> str:
    """Transforma resultados técnicos de DQ em narrativa de negócio."""

    failed_rules = [r for r in dq_results['rules'] if r['score'] < 0.85]
    if not failed_rules:
        return "✅ Qualidade de dados OK — todas as regras passaram."

    prompt = f"""Você é um especialista em governança de dados. Analise os resultados de qualidade
abaixo e gere um diagnóstico claro para o time de negócio (não técnico).

Contexto da tabela: {table_context}

Regras com problemas:
{json.dumps(failed_rules, indent=2, ensure_ascii=False)}

Para cada falha, explique:
1. O que está errado em linguagem simples
2. Provável causa (sistema de origem? transformação ETL? bug de ingestão?)
3. Impacto de negócio (relatórios afetados, riscos de compliance LGPD/BACEN)
4. Ação recomendada

Seja direto e conciso. Use bullet points."""

    resp = bedrock.converse(
        modelId='anthropic.claude-3-5-sonnet-20241022-v2:0',
        messages=[{"role": "user", "content": [{"text": prompt}]}],
        inferenceConfig={"maxTokens": 800, "temperature": 0.2}
    )
    return resp['output']['message']['content'][0]['text']

# Resultado real de Glue DQ (obtido via S3 ou CloudWatch após job)
dq_result_example = {
    "table": "orders_silver",
    "run_date": "2024-06-15",
    "rules": [
        {"rule": "IsComplete 'customer_cpf'",          "score": 0.69, "threshold": 0.95},
        {"rule": "ColumnValues 'order_value' >= 0",      "score": 0.998, "threshold": 1.0},
        {"rule": "Uniqueness 'order_id'",               "score": 0.82, "threshold": 1.0},
        {"rule": "IsComplete 'product_sku'",             "score": 0.91, "threshold": 0.99}
    ]
}

narrativa = generate_dq_narrative(
    dq_results=dq_result_example,
    table_context="Tabela de pedidos de e-commerce — alimenta dashboard de vendas e relatório BACEN mensal"
)
print(narrativa)
