01

O que é Bedrock Knowledge Bases?

RAG totalmente gerenciado: da ingestão de documentos à geração de respostas em uma única API.

Construir RAG do zero exige manter uma pipeline de ingestão, um Vector DB, um orquestrador de busca e a lógica de montagem de prompt — quatro sistemas separados. O Amazon Bedrock Knowledge Bases colapsa tudo isso em um serviço gerenciado:

Ingestão
Sync Automático
Conecta a fontes de dados (S3, Confluence, SharePoint, Salesforce, ServiceNow), extrai, chunkeia e indexa automaticamente. Job incremental ou agendado.
Armazenamento
Vector Store Gerenciado
OpenSearch Serverless (padrão), pgvector (Aurora/RDS), Pinecone, Redis Enterprise ou Mongo Atlas — você escolhe, a KB gerencia os índices.
Recuperação
Retrieve + Generate
API única: RetrieveAndGenerate faz busca semântica + injeção de contexto + chamada ao LLM de forma encadeada e auditável.

02

Fontes de Dados & Sincronização

Conectores nativos, sincronização incremental e metadados de filtragem.

O Knowledge Bases suporta 5 fontes de dados nativas. Cada fonte tem um conector gerenciado que extrai texto, metadados e mantém histórico de sincronização incremental — apenas documentos novos ou modificados são re-processados:

Fontes Suportadas
  • ☁️ Amazon S3 — PDF, DOCX, TXT, MD, HTML, CSV
  • 📘 Confluence — Espaços, páginas e attachments
  • 📂 SharePoint Online — Sites, drives e listas
  • ⚡ Salesforce — Cases, artigos de knowledge
  • 🎫 ServiceNow — Artigos e incidentes
Modos de Sync
  • 🔄 On Demand — Trigger manual ou via API
  • ⏰ Scheduled — Cron (mín. 1 hora)
  • 📡 EventBridge — S3 PutObject → sync imediato
  • 🗑️ Delete Sync — Remove vetores de docs deletados
  • 🔖 Metadata Filters — Filtra por tag/campo no Retrieve

Código: Criar KB e disparar sync via Boto3

import boto3

bedrock_agent = boto3.client("bedrock-agent", region_name="us-east-1")

# Criar Knowledge Base
kb = bedrock_agent.create_knowledge_base(
    name="produto-kb",
    roleArn="arn:aws:iam::123456789:role/BedrockKBRole",
    knowledgeBaseConfiguration={
        "type": "VECTOR",
        "vectorKnowledgeBaseConfiguration": {
            "embeddingModelArn": "arn:aws:bedrock:us-east-1::foundation-model/amazon.titan-embed-text-v2:0"
        }
    },
    storageConfiguration={
        "type": "OPENSEARCH_SERVERLESS",
        "opensearchServerlessConfiguration": {
            "collectionArn": "arn:aws:aoss:us-east-1:123456789:collection/kb-vectors",
            "vectorIndexName": "produto-index",
            "fieldMapping": {
                "vectorField": "embedding",
                "textField": "text",
                "metadataField": "metadata"
            }
        }
    }
)
kb_id = kb["knowledgeBase"]["knowledgeBaseId"]

# Criar Data Source (S3)
ds = bedrock_agent.create_data_source(
    knowledgeBaseId=kb_id,
    name="s3-docs",
    dataSourceConfiguration={
        "type": "S3",
        "s3Configuration": {
            "bucketArn": "arn:aws:s3:::minha-kb-docs",
            "inclusionPrefixes": ["docs/", "releases/"]
        }
    },
    vectorIngestionConfiguration={
        "chunkingConfiguration": {
            "chunkingStrategy": "SEMANTIC",  # ou FIXED_SIZE / HIERARCHICAL
            "semanticChunkingConfiguration": {
                "maxTokens": 300,
                "bufferSize": 1,
                "breakpointPercentileThreshold": 95
            }
        }
    }
)

# Disparar sincronização
bedrock_agent.start_ingestion_job(
    knowledgeBaseId=kb_id,
    dataSourceId=ds["dataSource"]["dataSourceId"]
)

Estratégias de Chunking

Fixed-Size, Semantic, Hierarchical — e como escolher para cada caso de uso.

Fixed-Size
Chunks de Tamanho Fixo
Divide o texto em blocos de N tokens com overlap de M%. Simples e previsível. Risco: cortar no meio de uma frase. Ideal para documentos técnicos uniformes.
Semantic
Chunking Semântico
Detecta mudança de tópico por similaridade de sentenças (percentile threshold). Chunks têm significado completo. Melhor para FAQs, políticas e contratos.
Hierarchical
Chunks Hierárquicos
Produz chunks pai (contexto longo, ~1500 tokens) e filho (trecho específico, ~300 tokens). O retrieve usa o filho para precisão e o pai para contexto. Melhor para documentação estruturada.
💡 Regra de Ouro para Chunking
Comece com Semantic para maioria dos casos. Mude para Hierarchical se os usuários fazem perguntas que exigem contexto maior que um parágrafo. Use Fixed-Size apenas para documentos tabelares ou com estrutura muito regular.

APIs: Retrieve vs RetrieveAndGenerate

Quando usar cada endpoint e como filtrar por metadados.

Retrieve — só busca

Retorna os chunks mais relevantes sem chamar o LLM. Use quando você quer controlar o prompt ou agregar resultados de múltiplas fontes antes de gerar.

rt = boto3.client("bedrock-agent-runtime")

resp = rt.retrieve(
    knowledgeBaseId="kb-abc123",
    retrievalQuery={"text": "Como funciona o processo de onboarding?"},
    retrievalConfiguration={
        "vectorSearchConfiguration": {
            "numberOfResults": 5,
            "filter": {
                "equals": {
                    "key": "departamento",
                    "value": "RH"
                }
            }
        }
    }
)
for r in resp["retrievalResults"]:
    print(r["content"]["text"][:200])
    print(r["score"])  # similaridade
RetrieveAndGenerate — RAG completo

Busca + injeta contexto + chama o LLM em uma única chamada. Retorna resposta gerada com citações (source attribution).

resp = rt.retrieve_and_generate(
    input={"text": "Quais são as políticas de férias?"},
    retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            "knowledgeBaseId": "kb-abc123",
            "modelArn": "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-3-5-sonnet-20241022-v2:0",
            "retrievalConfiguration": {
                "vectorSearchConfiguration": {
                    "numberOfResults": 4,
                    "overrideSearchType": "HYBRID"  # vector + BM25
                }
            },
            "generationConfiguration": {
                "promptTemplate": {
                    "textPromptTemplate": "Responda em português baseando-se estritamente no contexto: $search_results$\n\nPergunta: $query$"
                }
            }
        }
    }
)
print(resp["output"]["text"])
# Source attribution (citações)
for citation in resp.get("citations", []):
    for ref in citation.get("retrievedReferences", []):
        print(ref["location"]["s3Location"]["uri"])

Busca Híbrida & Query Reformulation

Combinando busca vetorial e BM25 para máxima precisão.

A busca vetorial (similaridade semântica) é forte para conceitos e sinônimos, mas fraca para termos exatos (números de produto, códigos, nomes próprios). O BM25 é o inverso — exato mas sem semântica. A busca híbrida combina os dois scores com Reciprocal Rank Fusion (RRF):

✅ Quando ativar Hybrid Search
Ative overrideSearchType: "HYBRID" sempre que os usuários mencionam IDs de produto, nomes de arquivo, versões, datas ou termos de jargão técnico específico da empresa. Para perguntas puramente conceituais, o modo vetorial padrão é suficiente.
