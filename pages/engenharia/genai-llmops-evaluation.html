LLMOps & Model Evaluation

Métricas de avaliação de RAG (RAGAS), Observabilidade e Tracing da cadeia de pensamento.

01

O Problema da Avaliação em GenAI

Diferente do Machine Learning tradicional (onde você avalia a acurácia ou RMSE), avaliar textos é muito mais subjetivo.

Como saber matematicamente se a resposta de um RAG (Retrieval-Augmented Generation) foi "boa" ou "ruim"? É aqui que entram os frameworks de Evaluation e a disciplina de LLMOps.

Avaliação

Model Evaluation

Medir sistematicamente a qualidade (Alucinação, Relevância, Fidelidade) das respostas geradas pelo seu LLM contra um Ground Truth.

Tracing

Observability

Monitorar o pipeline em produção. Capturar o Prompt, a latência do VectorDB e a cadeia de pensamento (CoT) dos agentes.

Governança

Prompt Tracking

Versionar prompts como código (Git) ou no MLflow. Evita o caos de não saber qual prompt gerou qual resposta.

02

Avaliando RAG (Framework RAGAS)

O RAGAS é o padrão de mercado para avaliar sistemas de recuperação e geração.

O RAGAS (Retrieval Augmented Generation Assessment) isola a avaliação em dois eixos: Retriever (A busca no banco foi boa?) e Generator (O LLM gerou a resposta certa?).

Métrica (RAGAS) Avalia o quê? Pergunta Chave Como resolver pontuação baixa?
Faithfulness Generation A resposta foi baseada APENAS no contexto recuperado? (Evita alucinação) Melhorar o Prompt (Ex: "Não use conhecimento prévio.")
Answer Relevance Generation A resposta gerada realmente responde à pergunta inicial? Usar um LLM mais inteligente (Claude 3.5 Sonnet).
Context Precision Retrieval Os chunks mais relevantes foram retornados no TOPO da busca? Adicionar um Re-ranker (ex: Cohere ReRank).
Context Recall Retrieval O contexto tem informações suficientes para responder? Melhorar a estratégia de Chunking ou Busca Híbrida.

Trade-off: LLM-as-a-Judge vs HITL

Fator RAGAS (LLM-as-a-Judge) Human-in-the-Loop (HITL)
Velocidade e Escala Avalia 10.000 respostas em minutos via API. Lento. Requer SMEs (Subject Matter Experts) lendo texto.
Precisão de Domínio Pode cometer erros sutis em jargões médicos ou legais muito específicos se não for "ensinado". Altíssima precisão. O humano sabe o contexto real da empresa.
Custo Custo variável (Tokens da API do LLM Juiz). Custo fixo altíssimo (Salário do Especialista em Dados).
Veredito AWS Obrigatório para CI/CD e testes diários em massa. Obrigatório apenas para criação do Golden Dataset base.
03

Arquitetura de Observabilidade (Tracing)

Monitorando o pipeline em produção na nuvem da AWS.

Quando você constrói Agentes, um simples prompt gera múltiplas chamadas à API, queries no banco e decisões. Sem Tracing, você fica cego.

📌 Legenda & Arquitetura — Pipeline de Observabilidade e LLMOps:
  • Componentes AWS / Módulos: Amazon API Gateway, AWS Lambda (LangChain), Amazon Bedrock, Amazon CloudWatch (Invocation Logs), MLflow / LangSmith Trace Server.
  • Integração: Chamadas orquestradas via Lambda/LangChain com captura automatizada de logs no CloudWatch e telemetria distribuída via callbacks para LangSmith/MLflow.
  • Contexto: Rastreamento end-to-end (tracing), monitoramento de latência, uso de tokens e avaliação contínua em LLMOps.

04

CI/CD para Prompts — Versionamento e Gate de Qualidade

Prompts são código: versionar no S3, avaliar com RAGAS em cada PR, bloquear regressões.

Prompts mudam com frequência e cada alteração pode degradar a qualidade silenciosamente. A solução é tratar prompts como artefatos de software: armazenar versões no S3, avaliar automaticamente com RAGAS em cada Pull Request, e usar o score de faithfulness como gate de qualidade — bloqueando merges que causem regressão.

Prompt Registry + Avaliação Automática no CI/CD
import boto3, json, sys
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy

s3 = boto3.client("s3")
BUCKET = "meu-prompt-registry"

def get_prompt(nome: str, versao: str = "latest") -> str:
    obj = s3.get_object(Bucket=BUCKET, Key=f"prompts/{nome}/{versao}.txt")
    return obj["Body"].read().decode()

def publicar_prompt(nome: str, conteudo: str, versao: str) -> None:
    for key in [f"prompts/{nome}/{versao}.txt", f"prompts/{nome}/latest.txt"]:
        s3.put_object(Bucket=BUCKET, Key=key, Body=conteudo.encode())
    print(f"Prompt '{nome}' v{versao} publicado.")

def avaliar_prompt(nome: str, test_set: list) -> dict:
    """test_set: lista de dicts com keys question, answer, contexts, ground_truth"""
    dataset = Dataset.from_list(test_set)
    scores = evaluate(dataset, metrics=[faithfulness, answer_relevancy])
    return {
        "faithfulness":     round(scores["faithfulness"], 4),
        "answer_relevancy": round(scores["answer_relevancy"], 4),
        "prompt":           nome,
    }

def ci_gate(scores: dict, threshold: float = 0.80) -> None:
    print(json.dumps(scores, indent=2))
    if scores["faithfulness"] < threshold:
        print(f"❌ CI falhou: faithfulness={scores['faithfulness']} abaixo de {threshold}. PR bloqueado.")
        sys.exit(1)
    print(f"✅ CI aprovado: faithfulness={scores['faithfulness']}")

# Uso no pipeline (ex: GitHub Actions / CodeBuild)
if __name__ == "__main__":
    test_data = [
        {
            "question":    "Qual é o prazo de entrega?",
            "answer":      "O prazo é de 5 dias úteis.",
            "contexts":    ["Política: entregas em até 5 dias úteis a partir da confirmação."],
            "ground_truth": "5 dias úteis",
        }
    ]
    scores = avaliar_prompt("prompt-atendimento-v2", test_data)
    ci_gate(scores)
