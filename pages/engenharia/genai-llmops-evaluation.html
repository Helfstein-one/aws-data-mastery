07

O Problema da Avaliação em GenAI

Diferente do Machine Learning tradicional (onde você avalia a acurácia ou RMSE), avaliar textos é muito mais subjetivo.

Como saber matematicamente se a resposta de um RAG (Retrieval-Augmented Generation) foi "boa" ou "ruim"? É aqui que entram os frameworks de Evaluation e a disciplina de LLMOps.

Avaliação

Model Evaluation

Medir sistematicamente a qualidade (Alucinação, Relevância, Fidelidade) das respostas geradas pelo seu LLM contra um Ground Truth.

Tracing

Observability

Monitorar o pipeline em produção. Capturar o Prompt, a latência do VectorDB e a cadeia de pensamento (CoT) dos agentes.

Governança

Prompt Tracking

Versionar prompts como código (Git) ou no MLflow. Evita o caos de não saber qual prompt gerou qual resposta.

07.1

Avaliando RAG (Framework RAGAS)

O RAGAS é o padrão de mercado para avaliar sistemas de recuperação e geração.

O RAGAS (Retrieval Augmented Generation Assessment) isola a avaliação em dois eixos: Retriever (A busca no banco foi boa?) e Generator (O LLM gerou a resposta certa?).

Métrica (RAGAS) Avalia o quê? Pergunta Chave Como resolver pontuação baixa?
Faithfulness Generation A resposta foi baseada APENAS no contexto recuperado? (Evita alucinação) Melhorar o Prompt (Ex: "Não use conhecimento prévio.")
Answer Relevance Generation A resposta gerada realmente responde à pergunta inicial? Usar um LLM mais inteligente (Claude 3.5 Sonnet).
Context Precision Retrieval Os chunks mais relevantes foram retornados no TOPO da busca? Adicionar um Re-ranker (ex: Cohere ReRank).
Context Recall Retrieval O contexto tem informações suficientes para responder? Melhorar a estratégia de Chunking ou Busca Híbrida.

Trade-off: LLM-as-a-Judge vs HITL

Fator RAGAS (LLM-as-a-Judge) Human-in-the-Loop (HITL)
Velocidade e Escala Avalia 10.000 respostas em minutos via API. Lento. Requer SMEs (Subject Matter Experts) lendo texto.
Precisão de Domínio Pode cometer erros sutis em jargões médicos ou legais muito específicos se não for "ensinado". Altíssima precisão. O humano sabe o contexto real da empresa.
Custo Custo variável (Tokens da API do LLM Juiz). Custo fixo altíssimo (Salário do Especialista em Dados).
Veredito AWS Obrigatório para CI/CD e testes diários em massa. Obrigatório apenas para criação do Golden Dataset base.

Arquitetura de Observabilidade (Tracing)

Monitorando o pipeline em produção na nuvem da AWS.

Quando você constrói Agentes, um simples prompt gera múltiplas chamadas à API, queries no banco e decisões. Sem Tracing, você fica cego.

Monitorando o Pipeline (Output em formato MLflow) 
Trace ID: 9f8a-3c2b (Latência Total: 3.4s | Custo Total: $0.003)

└─ User Input: "Quantos clientes temos em atraso e quem é o devedor mestre?"

   │  └─ Output: SELECT COUNT(*) FROM tb_clientes WHERE status = 'atraso'
   ├─ Tool: Vector Search (Latência: 0.5s | Documents: 3)

   └─ LLM Synthesize (Latência: 1.7s | Tokens: 850)
