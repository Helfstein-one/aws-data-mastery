Conceito

Data Contract: O Contato entre Sistemas

Um Data Contract é uma especificação explícita de como os dados fluem entre sistemas. Define schema, versioning, SLAs, e conformidade. Essencial em arquiteturas event-driven.

Elemento

Schema

JSON Schema ou Avro. Define campos obrigatórios, tipos, validações.

Elemento

Versioning

Versionamento semântico. Compatibilidade retroativa garantida.

Elemento

SLA

Latência, throughput, disponibilidade esperada.

Elemento

Conformidade

GDPR, BACEN, auditoria. Provenance dos dados.

04
Evolução de Contrato

Versionamento Semântico e Retrocompatibilidade

Dados evoluem. Contratos devem suportar múltiplas versões simultaneamente. Versionamento semântico garante compatibilidade: MAJOR.MINOR.PATCH.

Versão Mudança Tipo Compatibilidade
1.0.0 Initial release - -
1.1.0 Adicionar campo opcional: riskScore MINOR ✅ Retrocompatível
1.2.0 Adicionar campo opcional: approvalTime MINOR ✅ Retrocompatível
2.0.0 Remover campo: decisionReason (obrigatório agora) MAJOR ❌ Quebra compatibilidade
🎯 Regra de Ouro:

Campos novos são sempre OPCIONAIS. Remover ou alterar existentes é MAJOR. Consumidores devem suportar no mínimo 2 versões de um schema.

Conclusão

Data Contracts para Qualidade

🎯 Takeaways Principais

  • Contrato Explícito: Schema define contrato entre produtor/consumidor
  • Validação: Em múltiplas camadas (publicação, persistência, consumo)
  • Versionamento: Semântico garante compatibilidade
  • Governança: Conformidade com BACEN, GDPR, auditoria
  • Qualidade: Reduz bugs, facilita evolução
