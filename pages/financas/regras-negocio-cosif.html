01
Finite State Machine

Ciclo de Vida de uma Operação de Crédito

Toda operação de crédito passa por um conjunto bem-definido de estados. A Finite State Machine (FSM) garante que as transições sejam válidas, auditáveis e conformes com as regras COSIF (Catálogo de Operações do Sistema Financeiro). Cada estado corresponde a uma situação contábil e regulatória específica.

🎯 Estados Principais:

NOVO: Contrato criado, não liberado ainda.
ATIVO: Contrato em execução, cliente pode usar limite.
VENCIDO: Data de vencimento chegou, sem atraso ainda.
ATRASADO: Dias em atraso > 0. Pode levar a risco de crédito.
LIQUIDADO: Operação finalizada, saldo zerado.
ENCERRADO: Arquivo histórico, sem movimentação.

Conformidade Contábil

Mapeamento COSIF por Estado

COSIF (Catálogo de Operações do Sistema Financeiro) define como cada operação deve ser contabilizada. Diferentes estados de crédito mapeiam para diferentes contas COSIF, garantindo conformidade contábil.

💡 Código Pseudológico - Validação de Transição
function validateTransition(fromState, toState, event) {
  const validTransitions = FSM_MATRIX[fromState];

  if (!validTransitions.includes(toState)) {
    throw new InvalidTransitionError(
      `${fromState} → ${toState} não é permitida para ${event}`
    );
  }

  // Validações de negócio
  if (toState === 'ATRASADO' && diasAtraso < 1) {
    throw new BusinessRuleError('Dias em atraso deve ser >= 1');
  }

  // Disparar evento
  emitEvent('CreditState.Transitioned', {
    from: fromState,
    to: toState,
    event: event,
    timestamp: now()
  });

  return true;
}

🎯 Takeaways Principais

  • FSM Matrix: Define todas as transições válidas entre estados
  • Estados: NOVO → ATIVO → VENCIDO/ATRASADO → LIQUIDADO → ENCERRADO
  • COSIF: Cada estado mapeia para contas contábeis específicas
  • Automação: Transições disparam eventos contábeis automáticos
  • Auditoria: Todas as transições são rastreadas e imutáveis
  • Conformidade: Garante aderência a BACEN e IFRS 9
