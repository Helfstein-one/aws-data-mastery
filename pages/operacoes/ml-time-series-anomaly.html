Time Series & Anomaly Detection

Da teoria de séries temporais (ARIMA, Prophet) ao Amazon Forecast gerenciado e detecção de anomalias em tempo real com SageMaker Random Cut Forest e CloudWatch Anomaly Detection.

01

Fundamentos de Séries Temporais

Tendência, sazonalidade, ruído e estacionariedade — os 4 pilares antes de qualquer modelo.

Decomposição
Componentes de uma Série
Tendência (T): direção de longo prazo. Sazonalidade (S): padrão periódico (diário, semanal, anual). Ciclo (C): flutuações de longo prazo não-periódicas. Ruído (ε): variação aleatória irredutível.
Pré-requisito
Estacionariedade
Série é estacionária quando média, variância e autocovariância não mudam com o tempo. ARIMA requer estacionariedade. Teste: ADF (Augmented Dickey-Fuller). Solução: diferenciação (d=1 ou d=2).
Avaliação
Métricas de Forecast
MAE: erro absoluto médio — interpretável. RMSE: penaliza outliers. MAPE: percentual médio (cuidado com y≈0). WAPE/SMAPE: variantes robustas. Backtest: Walk-forward validation.
02

ARIMA & Prophet

O modelo clássico e o modelo do Facebook/Meta para séries com múltiplas sazonalidades.

ARIMA(p, d, q)

p: lags de autocorrelação (AR). d: ordem de diferenciação. q: ordem de média móvel (MA). Use auto_arima do pmdarima para encontrar (p,d,q) automaticamente.

from pmdarima import auto_arima
import pandas as pd

df = pd.read_csv("vendas.csv", parse_dates=["data"], index_col="data")

model = auto_arima(
    df["vendas"],
    seasonal=True,
    m=12,            # sazonalidade mensal
    stepwise=True,
    suppress_warnings=True,
    information_criterion="aic"
)
print(model.summary())

# Forecast 6 meses
forecast, conf_int = model.predict(n_periods=6, return_conf_int=True)
Prophet (Meta)

Modelo aditivo com suporte a múltiplas sazonalidades (anual, semanal, diária), feriados, e mudanças de tendência (changepoints) automáticas. Robusto a dados faltantes.

from prophet import Prophet
import pandas as pd

df = pd.read_csv("vendas.csv")
df = df.rename(columns={"data": "ds", "vendas": "y"})

m = Prophet(
    seasonality_mode="multiplicative",  # ou additive
    changepoint_prior_scale=0.05,       # flexibilidade da tendência
    yearly_seasonality=True,
    weekly_seasonality=True,
    daily_seasonality=False
)

# Adicionar feriados brasileiros
m.add_country_holidays(country_name="BR")

m.fit(df)

future = m.make_future_dataframe(periods=90, freq="D")
forecast = m.predict(future)

# Plotar componentes
fig = m.plot_components(forecast)
💡 Quando usar cada um
ARIMA: univariado, série única, dados estacionários/estacionárizáveis. Prophet: múltiplas sazonalidades, feriados, dados faltantes, stakeholders não-técnicos (output intuitivo). Amazon Forecast: dezenas/centenas de séries com features externas (preço, clima, promoções).
03

Amazon Forecast

Forecasting gerenciado para múltiplas séries com AutoML, features externas e quantis de incerteza.

AMAZON FORECAST — PIPELINE GERENCIADO
📌 Legenda — Amazon Forecast Pipeline:
  • Componentes AWS: S3 (dados), Dataset Group, Predictor (AutoML/DeepAR+/CNN-QR), Forecast (quantis p10/p50/p90), Export Job.
  • Integração: Target Time Series obrigatório; Related Time Series (features externas: preço, clima, promoção) opcional mas aumenta precisão significativamente.
  • Contexto: Suporta milhares de séries temporais simultâneas com AutoML — encontra o melhor algoritmo por série.
import boto3

forecast = boto3.client("forecast")

# 1. Dataset Group
dsg = forecast.create_dataset_group(
    DatasetGroupName="varejo-forecast",
    Domain="RETAIL"
)

# 2. Dataset (Target Time Series)
ds = forecast.create_dataset(
    DatasetName="vendas-diarias",
    Domain="RETAIL",
    DatasetType="TARGET_TIME_SERIES",
    DataFrequency="D",  # diário
    Schema={
        "Attributes": [
            {"AttributeName": "item_id",   "AttributeType": "string"},
            {"AttributeName": "timestamp", "AttributeType": "timestamp"},
            {"AttributeName": "demand",    "AttributeType": "float"}
        ]
    }
)

# 3. Importar dados do S3
forecast.create_dataset_import_job(
    DatasetImportJobName="import-jan-2025",
    DatasetArn=ds["DatasetArn"],
    DataSource={"S3Config": {
        "Path": "s3://meu-bucket/forecast/target/",
        "RoleArn": "arn:aws:iam::123:role/ForecastRole"
    }},
    TimestampFormat="yyyy-MM-dd"
)

# 4. Criar Predictor com AutoML
predictor = forecast.create_auto_predictor(
    PredictorName="predictor-automl-v1",
    ForecastHorizon=30,        # 30 dias à frente
    ForecastFrequency="D",
    DataConfig={
        "DatasetGroupArn": dsg["DatasetGroupArn"]
    },
    OptimizationMetric="WAPE"  # Weighted Absolute Percentage Error
)

# 5. Gerar Forecast
fc = forecast.create_forecast(
    ForecastName="forecast-fev-2025",
    PredictorArn=predictor["PredictorArn"],
    ForecastTypes=["0.1", "0.5", "0.9"]  # p10, p50, p90
)

Detecção de Anomalias — SageMaker Random Cut Forest

Algoritmo não-supervisionado para streaming de dados — sem labels necessários.

O Random Cut Forest (RCF) do SageMaker é um algoritmo de detecção de anomalias baseado em floresta aleatória de cortes. A ideia: pontos anômalos requerem menos cortes para serem isolados da árvore — seu "anomaly score" é inversamente proporcional à profundidade média de isolamento.

RCF — Treinamento Batch + Inferência Streaming
from sagemaker import RandomCutForest

rcf = RandomCutForest(
    role=role,
    instance_count=1,
    instance_type="ml.m5.large",
    data_location=f"s3://{bucket}/rcf-train/",
    output_path=f"s3://{bucket}/rcf-output/",
    num_samples_per_tree=512,
    num_trees=50
)

rcf.fit(rcf.record_set(X_train.values.astype("float32")))

predictor = rcf.deploy(
    initial_instance_count=1,
    instance_type="ml.m5.large"
)

# Inferência em tempo real
scores = predictor.predict(X_stream.values.astype("float32"))

# Threshold: média + 3 desvios padrão dos scores de treino
import numpy as np
score_mean = np.mean(scores["scores"])
score_std  = np.std(scores["scores"])
threshold  = score_mean + 3 * score_std

anomalies = [i for i, s in enumerate(scores["scores"]) if s > threshold]
print(f"Anomalias detectadas: {anomalies}")
CloudWatch Anomaly Detection

Para métricas operacionais (latência de API, erros, throughput), o CloudWatch tem detecção de anomalias nativa baseada em ML — sem código, sem infraestrutura:

cw = boto3.client("cloudwatch")

# Criar modelo de anomalia para métrica existente
cw.put_anomaly_detector(
    Namespace="AWS/Lambda",
    MetricName="Duration",
    Dimensions=[{"Name": "FunctionName", "Value": "meu-processor"}],
    Stat="Average",
    Configuration={
        "ExcludedTimeRanges": [
            # Excluir janelas de manutenção
            {"StartTime": "2025-01-01T02:00:00Z",
             "EndTime":   "2025-01-01T04:00:00Z"}
        ],
        "MetricTimezone": "America/Sao_Paulo"
    }
)

# Criar alarme baseado em anomalia (sem threshold fixo)
cw.put_metric_alarm(
    AlarmName="lambda-duration-anomaly",
    ComparisonOperator="GreaterThanUpperThreshold",
    EvaluationPeriods=3,
    Metrics=[{
        "Id": "m1",
        "MetricStat": {
            "Metric": {"Namespace": "AWS/Lambda", "MetricName": "Duration",
                       "Dimensions": [{"Name": "FunctionName", "Value": "meu-processor"}]},
            "Period": 300,
            "Stat": "Average"
        }
    }, {
        "Id": "ad1",
        "Expression": "ANOMALY_DETECTION_BAND(m1, 2)",
        "Label": "Duration (expected)"
    }],
    ThresholdMetricId="ad1",
    AlarmActions=["arn:aws:sns:us-east-1:123:alerta-anomalia"]
)
