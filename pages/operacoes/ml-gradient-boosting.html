Gradient Boosting: XGBoost & LightGBM

Os algoritmos dominantes em dados tabulares — desde Kaggle até modelos de crédito em produção. Teoria de ensemble boosting, diferenças entre XGBoost e LightGBM, SageMaker built-in e interpretabilidade com SHAP.

01

Ensemble: Boosting vs Bagging vs Stacking

Por que combinar modelos fracos é mais poderoso que um modelo forte único.

Paralelo
Bagging (Random Forest)
Treina N árvores em paralelo em amostras bootstrap do dataset. Reduz variância (overfitting). Cada árvore vota → maioria (classificação) ou média (regressão). Robusto mas limitado em bias.
Sequencial
Boosting (XGBoost/LightGBM)
Treina árvores em sequência — cada nova árvore foca nos resíduos (erros) da anterior. Reduz bias E variância progressivamente. Mais poderoso que bagging mas mais sensível a overfitting.
Meta-modelo
Stacking
Usa as previsões de N modelos base como features para um meta-modelo (geralmente regressão logística ou XGBoost). Combina os pontos fortes de cada modelo base. Mais complexo de manter em produção.

02

XGBoost — eXtreme Gradient Boosting

Regularização L1/L2 nativa, DART, Missing Values automático e built-in SageMaker.

Hiperparâmetros Críticos

Controle de Overfitting
  • learning_rate (η) — 0.01–0.3 (menor = mais árvores necessárias)
  • max_depth — 3–10 (padrão=6; profundidade controla interações)
  • n_estimators — 100–5000 (use early_stopping_rounds)
  • subsample — 0.5–1.0 (fração de linhas por árvore)
  • colsample_bytree — 0.5–1.0 (fração de features por árvore)
  • reg_alpha (L1) — Esparsidade de pesos nas folhas
  • reg_lambda (L2) — Suavização (padrão=1)
Funções de Perda (objective)
  • binary:logistic — Classificação binária
  • multi:softmax — Multiclasse (retorna classe)
  • multi:softprob — Multiclasse (retorna probabilidade)
  • reg:squarederror — Regressão (MSE)
  • reg:tweedie — Distribuição Tweedie (seguros)
  • rank:pairwise — Learning to Rank

XGBoost no SageMaker (Built-in Algorithm)

import sagemaker
from sagemaker.inputs import TrainingInput

role = sagemaker.get_execution_role()
session = sagemaker.Session()

# Usar imagem built-in do XGBoost no SageMaker
container = sagemaker.image_uris.retrieve("xgboost", session.boto_region_name, version="1.7-1")

xgb = sagemaker.estimator.Estimator(
    image_uri=container,
    role=role,
    instance_count=1,
    instance_type="ml.m5.xlarge",
    output_path=f"s3://{session.default_bucket()}/xgboost-output",
    sagemaker_session=session
)

# Hiperparâmetros
xgb.set_hyperparameters(
    objective="binary:logistic",
    num_round=500,
    max_depth=6,
    eta=0.1,
    subsample=0.8,
    colsample_bytree=0.8,
    eval_metric="auc",
    early_stopping_rounds=20,
    scale_pos_weight=3  # para dataset desbalanceado
)

# Training data
train_input = TrainingInput(f"s3://meu-bucket/train/", content_type="csv")
val_input   = TrainingInput(f"s3://meu-bucket/val/",   content_type="csv")

xgb.fit({"train": train_input, "validation": val_input})

# Deploy
predictor = xgb.deploy(
    initial_instance_count=1,
    instance_type="ml.m5.large"
)

Convergência do Treinamento — Learning Curve com Early Stopping

💡 Caso de Uso: Previsão de Demanda de Produtos
Em um modelo de previsão de demanda, o log loss de treino continua caindo indefinidamente conforme o boosting adiciona árvores — mas o log loss de validação para de melhorar por volta do round 120 e volta a subir: o modelo está memorizando ruído do histórico de vendas em vez de aprender o padrão real. Definir early_stopping_rounds (ex: 20-50) interrompe o treinamento automaticamente nesse ponto ótimo, evitando overfitting e economizando tempo de treino.
03

LightGBM — Light Gradient Boosting Machine

Leaf-wise growth, GOSS, EFB — por que é 10x mais rápido que XGBoost em datasets grandes.

Crescimento
Leaf-Wise Growth
XGBoost cresce em nível (todos os nós do mesmo nível juntos). LightGBM cresce na folha com maior ganho de informação. Resulta em árvores mais assimétricas mas com menor perda mais rápido.
Amostragem
GOSS
Gradient-based One-Side Sampling: mantém instâncias com gradiente alto (erros grandes) e descarta uma fração aleatória das instâncias de gradiente baixo. Reduz dados sem perda de informação crítica.
Features
EFB
Exclusive Feature Bundling: agrupa features mutuamente exclusivas (raramente não-zero ao mesmo tempo) em uma única feature. Reduz dimensionalidade efetiva sem perda de informação.

from sklearn.model_selection import train_test_split

X_train, X_val, y_train, y_val = train_test_split(X, y, test_size=0.2)

# Suporte nativo a categorias (sem necessidade de one-hot encoding)
ds_train = lgb.Dataset(X_train, label=y_train, categorical_feature=["regiao", "segmento"])
ds_val   = lgb.Dataset(X_val,   label=y_val,   reference=ds_train)

params = {
    "objective": "binary",
    "metric": "auc",
    "learning_rate": 0.05,
    "num_leaves": 63,          # leaf-wise: 2^max_depth - 1 como referência
    "min_child_samples": 20,   # mínimo de amostras por folha (anti-overfitting)
    "feature_fraction": 0.8,   # colsample equivalente
    "bagging_fraction": 0.8,
    "bagging_freq": 5,
    "lambda_l1": 0.1,
    "verbose": -1
}

model = lgb.train(
    params,
    ds_train,
    num_boost_round=2000,
    valid_sets=[ds_val],
    callbacks=[lgb.early_stopping(50), lgb.log_evaluation(100)]
)

print(f"Best iteration: {model.best_iteration}, AUC: {model.best_score['valid_0']['auc']:.4f}")
04

SHAP Values — Interpretabilidade de Modelos

Feature importance global vs importância local por predição individual.

Feature importance padrão (gain/split count) diz quais features são importantes globalmente. SHAP (SHapley Additive exPlanations) explica por que o modelo fez aquela previsão específica para cada observação:

import shap

# SHAP nativo no XGBoost/LightGBM (rápido: Tree SHAP O(TLD²))
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X_val)

# Importância global (média do valor absoluto dos SHAP)
shap.summary_plot(shap_values, X_val, plot_type="bar")

# Waterfall plot: por que o modelo classificou ESTA observação como fraude?
shap.waterfall_plot(shap.Explanation(
    values=shap_values[0],           # primeira observação
    base_values=explainer.expected_value,
    data=X_val.iloc[0],
    feature_names=X_val.columns.tolist()
))

# Force plot: visualização interativa
shap.force_plot(
    explainer.expected_value,
    shap_values[0],
    X_val.iloc[0]
)
💡 SHAP em Modelos de Crédito
Regulações como LGPD e Basel III exigem explicabilidade em decisões de crédito automatizadas. SHAP permite gerar cartas de recusa com razões específicas: "Score reduzido em 15 pontos por renda_liquida abaixo de R$3.000" — direto e auditável.
