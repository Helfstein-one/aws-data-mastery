01

O que é MLOps? DevOps para Machine Learning

Por que a operacionalização de ML é fundamentalmente diferente de software tradicional.

MLOps (Machine Learning Operations) é a disciplina que aplica princípios DevOps ao desenvolvimento e implantação de sistemas de ML. Diferente do software tradicional, modelos de ML têm características únicas:

  1. Dados dinâmicos: O modelo não muda, mas os dados subjacentes mudam constantemente. Seu modelo de detecção de fraude de 2023 pode estar obsoleto em 2024 porque os padrões fraudulentos evoluem.
  2. Retrainamento contínuo: Você precisa retreinar regularmente à medida que novos dados chegam, sem parar de servir o modelo antigo.
  3. Monitoramento não é apenas logs: Você precisa monitorar a qualidade das predições, não apenas CPU/memória. Se o accuracy caiu de 95% para 85%, você precisa saber imediatamente.
  4. Reprodutibilidade: Qual versão de dados foi usada? Qual versão do modelo? Qual seed aleatório? Tudo precisa ser rastreável.
ℹ️ Fato Surpresa: Estudos mostram que apenas ~5% do código em produção de ML é o próprio modelo. Os outros 95% são infraestrutura de dados, feature engineering, validação, monitoramento e CI/CD. MLOps trata desses 95%.

Na AWS, implementamos MLOps através de uma combinação de serviços: SageMaker Pipelines (orquestração), Model Registry (versionamento), SageMaker Model Monitor (monitoramento), e CI/CD (automação com CodePipeline, GitHub Actions ou Jenkins).

02

Core Concepts: Feature Engineering até Monitoring

Os pilares de uma estratégia MLOps robusta.

Dados
Feature Engineering & Store
A qualidade do modelo é limitada pela qualidade das features. Um Feature Store (como SageMaker Feature Store) é um repositório centralizado de features pré-computadas, reutilizáveis entre modelos. Exemplo: um "histórico de transações do cliente" é uma feature que pode ser usada por múltiplos modelos (fraude, risco de crédito, recomendação).
Treinamento
Training Pipeline & Orchestration
SageMaker Pipelines automatiza o fluxo: ingestão de dados → preprocessamento → treinamento → avaliação → registro. Funciona como um "CI/CD para ML". Ao invés de rodar scripts manualmente, a pipeline executa automaticamente quando novos dados chegam.
Produção
Model Versioning & Registry
O Model Registry rastreia todas as versões de um modelo: métricas de desempenho, data de treinamento, autor, dados usados, hiperparâmetros. Permite "rolar para trás" rapidamente se um modelo novo falhar em produção.
Deployment
A/B Testing & Canary Releases
Não coloque 100% do tráfego em um modelo novo de uma vez. Use A/B testing: 90% das requisições para o modelo antigo (estável), 10% para o novo. Monitore métricas. Se tudo bem, aumente para 50/50, depois 100%. Se algo der errado, reverta automaticamente.
Observabilidade
Model Monitoring & Drift Detection
Data Drift: Os dados de entrada mudaram (ex: padrões de transações). Model Drift: A qualidade das predições caiu. O SageMaker Model Monitor detecta ambas automaticamente e alerta.
Governança
Compliance, Bias & Explainability
Modelos de IA em produção precisam de auditoria: explicabilidade (SHAP), detecção de bias (FairML), conformidade regulatória (LGPD, GDPR). A AWS fornece ferramentas como SageMaker Clarify para isso.

Componentes da pilha MLOps na AWS e como se integram.

Um pipeline MLOps típico na AWS conecta esses serviços:

  • Componentes AWS / Módulos: Representação Vetorial, Estrutura Neural / Árvore de Decisão
  • Integração: Fluxo conceitual de dados e abstração matemática.

Fluxo completo de MLOps: dados brutos → limpeza (Glue) → features (Feature Store) → treinamento (SageMaker) → registro (Model Registry) → avaliação → deployment → monitoramento (Model Monitor) → CI/CD automatizado.

✅ Benefício: Quando uma drift é detectada, o CI/CD dispara automaticamente um novo treinamento. Se o novo modelo tem métricas melhores, é promovido a produção. Se piora, a versão anterior é mantida. Tudo sem intervenção manual.

Implementação Prática: Código em Produção

Exemplos funcionais com boto3, SageMaker SDK e Model Registry.

Exemplo 1: Training Job com SageMaker e Model Registry

Código Python que treina um modelo XGBoost, avalia e registra no Model Registry:

import boto3
import sagemaker
import pandas as pd
from sagemaker.estimator import Estimator
from sagemaker.model_monitor import DataCaptureConfig
from datetime import datetime

# Setup
session = sagemaker.Session()
role = sagemaker.get_execution_role()
bucket = session.default_bucket()
region = session.boto_region_name

# 1. DOWNLOAD DADOS DE TREINAMENTO (ex: S3)
s3_client = boto3.client('s3')
train_data_path = 's3://{}/ml/train/data.csv'.format(bucket)
test_data_path = 's3://{}/ml/test/data.csv'.format(bucket)

# Carregar dados para avaliação local
df_train = pd.read_csv(train_data_path)
print(f"Training data shape: {df_train.shape}")

# 2. CRIAR ESTIMADOR XGBOOST
xgb_estimator = Estimator(
    image_uri=sagemaker.image_uris.retrieve('xgboost', region, version='1.5-1'),
    role=role,
    instance_count=1,
    instance_type='ml.m5.xlarge',
    output_path='s3://{}/ml/model_artifacts/'.format(bucket),
    sagemaker_session=session,
    hyperparameters={
        'objective': 'binary:logistic',
        'max_depth': 5,
        'eta': 0.2,
        'gamma': 4,
        'min_child_weight': 6,
        'subsample': 0.8,
        'num_round': 100,
    }
)

# 3. TREINAR COM DATA CAPTURE ATIVADO (para Model Monitor)
data_capture_config = DataCaptureConfig(
    enabled=True,
    sampling_percentage=100,
    destination_s3_uri='s3://{}/datacapture'.format(bucket)
)

xgb_estimator.fit({'training': train_data_path}, logs=True)

# 4. AVALIAR MODELO
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score, roc_auc_score

predictions = xgb_estimator.model_data  # Endpoint predictions
y_true = pd.read_csv(test_data_path)['target'].values
y_pred = xgb_estimator.predict(test_data_path)

accuracy = accuracy_score(y_true, y_pred > 0.5)
precision = precision_score(y_true, y_pred > 0.5)
recall = recall_score(y_true, y_pred > 0.5)
f1 = f1_score(y_true, y_pred > 0.5)
auc = roc_auc_score(y_true, y_pred)

print(f"Model Metrics:")
print(f"  Accuracy:  {accuracy:.4f}")
print(f"  Precision: {precision:.4f}")
print(f"  Recall:    {recall:.4f}")
print(f"  F1-Score:  {f1:.4f}")
print(f"  AUC:       {auc:.4f}")

# 5. REGISTRAR NO MODEL REGISTRY
sm_client = boto3.client('sagemaker')

# Criar modelo no SageMaker
model_name = f"fraud-detection-xgb-{datetime.now().strftime('%Y%m%d%H%M%S')}"
sm_client.create_model(
    ModelName=model_name,
    PrimaryContainer={
        'Image': sagemaker.image_uris.retrieve('xgboost', region, version='1.5-1'),
        'ModelDataUrl': xgb_estimator.model_data,
    },
    ExecutionRoleArn=role,
)

# 6. REGISTRAR VERSÃO NO MODEL PACKAGE GROUP
import json

model_package_group = 'fraud-detection-models'
model_package_description = json.dumps({
    'accuracy': float(accuracy),
    'precision': float(precision),
    'recall': float(recall),
    'f1_score': float(f1),
    'auc': float(auc),
    'training_data': train_data_path,
    'test_data': test_data_path,
    'training_date': datetime.now().isoformat(),
})

try:
    sm_client.create_model_package_group(
        ModelPackageGroupName=model_package_group,
        ModelPackageGroupDescription='XGBoost Fraud Detection Pipeline'
    )
except sm_client.exceptions.ResourceInUseException:
    print(f"Model package group '{model_package_group}' already exists")

# Criar versão do modelo
response = sm_client.create_model_package(
    ModelPackageGroupName=model_package_group,
    ModelPackageDescription=model_package_description,
    ModelApprovalStatus='PendingManualApproval',  # Requer aprovação antes de produção
    InferenceSpecification={
        'Containers': [
            {
                'Image': sagemaker.image_uris.retrieve('xgboost', region, version='1.5-1'),
                'ModelDataUrl': xgb_estimator.model_data,
            }
        ],
        'SupportedContentTypes': ['text/csv', 'application/json'],
        'SupportedResponseMIMETypes': ['application/json'],
    }
)

print(f"\nModel registered successfully!")
print(f"Model Package ARN: {response['ModelPackageArn']}")
print(f"Status: {response['ModelApprovalStatus']}")

# 7. APROVAR MODELO (em produção, isso seria feito por um humano/pipeline de validação)

Exemplo 2: SageMaker Pipeline com Orchestração Automática

Cria um pipeline que roda automaticamente quando novos dados chegam:

from sagemaker.workflow.pipeline import Pipeline
from sagemaker.workflow.steps import ProcessingStep, TrainingStep
from sagemaker.processing import ScriptProcessor
from sagemaker.workflow.parameters import ParameterString, ParameterInteger

# Parâmetros da Pipeline
input_data = ParameterString(
    name='InputDataUrl',
    default_value='s3://my-bucket/ml/raw-data/'
)
model_approval_status = ParameterString(
    name='ModelApprovalStatus',
    default_value='PendingManualApproval'
)

# PASSO 1: Processamento de Dados (com Glue/Spark)
processor = ScriptProcessor(
    image_uri=sagemaker.image_uris.retrieve('python', region, version='3.8'),
    role=role,
    instance_count=1,
    instance_type='ml.m5.xlarge',
)

step_process = ProcessingStep(
    name='DataProcessing',
    processor=processor,
    job_arguments=['--input', input_data],
    code='s3://my-bucket/scripts/preprocessing.py',
)

# PASSO 2: Treinamento
xgb_estimator = Estimator(
    image_uri=sagemaker.image_uris.retrieve('xgboost', region, version='1.5-1'),
    role=role,
    instance_count=1,
    instance_type='ml.m5.xlarge',
    output_path='s3://{}/artifacts/'.format(bucket),
    sagemaker_session=session,
)

step_train = TrainingStep(
    name='ModelTraining',
    estimator=xgb_estimator,
    inputs={'training': step_process.properties.ProcessingOutputConfigs[0].S3Output.S3Uri},
)

# PASSO 3: Avaliação (condicional)
from sagemaker.workflow.conditions import ConditionGreaterThan, ConditionLessThan
from sagemaker.workflow.properties import ProcessingJobProperties
from sagemaker.workflow.step_collections import RegisterModel

step_register = RegisterModel(
    name='RegisterModel',
    estimator=xgb_estimator,
    model_data=step_train.properties.ModelArtifacts.S3ModelArtifacts,
    content_types=['text/csv'],
    response_types=['application/json'],
    inference_instances=['ml.m5.xlarge'],
    transform_instances=['ml.m5.xlarge'],
    model_package_group_name='fraud-detection-models',
    approval_status=model_approval_status,
)

# CRIAR E EXECUTAR A PIPELINE
pipeline = Pipeline(
    name='FraudDetectionPipeline',
    steps=[step_process, step_train, step_register],
)

pipeline.upsert(role_arn=role)
execution = pipeline.start(
    parameters={
        'InputDataUrl': 's3://my-bucket/ml/raw-data/',
        'ModelApprovalStatus': 'PendingManualApproval',
    }
)

print(f"Pipeline execution started: {execution.arn}")
# Pode ser monitorado em SageMaker Console → Pipelines

# SCHEDULE PARA RODAR AUTOMATICAMENTE A CADA 7 DIAS
import schedule
import time

def run_pipeline():
    execution = pipeline.start()
    print(f"Pipeline triggered at {datetime.now()}")

# schedule.every(7).days.do(run_pipeline)
# Ou usar EventBridge para schedule em produção
⚠️ Boas Práticas em Produção: Nunca use `.update_model_package()` com status "Approved" automaticamente. Implemente um estágio de validação humana ou pelo menos metriche automáticas rigorosas (ex: só aprovar se AUC > 0.96 E accuracy > 0.94). Um modelo ruim em produção é pior que nenhum modelo.

Jenkins vs GitHub Actions vs SageMaker Pipelines

Qual ferramenta de CI/CD escolher para seu pipeline ML?

Critério Jenkins GitHub Actions SageMaker Pipelines
Especialização CI/CD genérico (DevOps) CI/CD genérico (DevOps) ✅ ML-nativo
Orquestração ML ⚠️ Requer scripts customizados ⚠️ Requer scripts customizados ✅ Nativa (Processing, Training Steps)
Preço 💰 Self-hosted (infra própria) 💰💰 ~$0.008/min para runners 💰💰 $0.20 por step + compute
Escalabilidade ✅ Excelente (muitos plugins) ⚠️ Boa, mas pode ficar caro ✅ Automática no AWS
Integração AWS ⚠️ Via boto3 scripts ⚠️ Via boto3 scripts ✅ Integração nativa
Model Registry ❌ Não incluso ❌ Não incluso ✅ SageMaker Model Registry
Monitoramento de Drift ❌ Não incluso ❌ Não incluso ✅ SageMaker Model Monitor
Melhor Para Grandes empresas com DevOps forte, multi-nuvem Startups, repos GitHub, CI/CD simples ML workflows na AWS, AutoML, retraining
Exemplo Use Case Pipeline com Kubernetes, Spark, múltiplas linguagens Deploy de aplicação Python, validação de código Retrainamento automático de modelos, A/B testing

Recomendação: Abordagem Híbrida

Camada 1: SageMaker Pipelines

Use para orquestração ML: treinamento, avaliação, registro de modelos. Roda dentro da AWS, integrado com Model Registry e Monitor.

Camada 2: GitHub Actions / Jenkins

Use para CI/CD de código: testes de código, lint, versionamento de scripts. Dispara SageMaker Pipelines via boto3 quando código é commitado.

Resultado: SageMaker cuida de ML, GitHub Actions cuida de código. Separação de responsabilidades.
