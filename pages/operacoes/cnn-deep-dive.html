O que é CNN? Estrutura Hierárquica de Características

Por que CNNs dominam visão computacional e como elas exploram estrutura espacial.

Uma Convolutional Neural Network (CNN) é uma arquitetura de rede neural especializada em processar dados com estrutura espacial, como imagens. Diferentemente das redes neurais totalmente conectadas (que consideram todo pixel como independente), CNNs exploram a premissa fundamental da visão: pixels próximos são mais relacionados que pixels distantes.

Imagine tentar reconhecer um rosto em uma imagem. Seus olhos não processam cada pixel individualmente e indepentemente. Em vez disso, você procura por padrões locais: bordas (contornos dos olhos), formas (nariz), e gradualmente combina essas características em conceitos mais abstratos. CNNs funcionam exatamente assim.

Hierarquia de Características

Uma CNN moderna típica segue este fluxo hierárquico:

Camadas Iniciais

Detectam: Bordas, linhas, texturas simples.

Filtros pequenos (3×3) capturam gradientes e mudanças de cor.

Camadas Intermediárias

Detectam: Formas compostas, partes de objetos (olhos, bocas).

Combinação hierárquica de características simples.

Camadas Profundas

Detectam: Objetos inteiros (rostos, carros, gatos).

Reconhecimento de conceitos semanticamente ricos.

✅ Resultado: Este design hierárquico permite que CNNs aprendam representações eficientes de imagens com muito menos parâmetros que redes totalmente conectadas.

Conceitos-Chave: Convolução, Pooling, Stride, Padding & Receptive Field

Os componentes técnicos que fazem CNNs funcionarem.

Operação de Convolução

A convolução é o coração de uma CNN. Imagine um filtro (kernel) pequeno (ex: 3×3) deslizando sobre uma imagem. Em cada posição, o filtro multiplica seus pesos pelos valores de pixels correspondentes e soma o resultado. Este valor (chamado ativação) é armazenado em um mapa de características (feature map).

Esse processo é repetido para múltiplos filtros diferentes, cada um aprendendo a detectar padrões diferentes (bordas horizontais, verticais, círculos, etc.).

ℹ️ Intuição Visual: Pense no filtro como uma ferramenta de detecção. Um filtro treinado para detectar bordas verticais terá pesos que enfatizam mudanças de cor na direção horizontal. Quando desliza sobre uma vertical line, produz alta ativação. Sobre um fundo uniforme, produz baixa ativação.

Stride (Passo)

Stride é o número de pixels que o filtro se move a cada passo. Um stride de 1 move o filtro 1 pixel por vez. Um stride de 2 move 2 pixels, reduzindo espacialmente o feature map pela metade.

Trade-off: Stride maior = feature map menor = menos computação, mas potencialmente perda de informação espacial.

Padding (Preenchimento)

Padding adiciona pixels (tipicamente com valor 0) ao redor da imagem antes da convolução. Isso preserva o tamanho espacial da imagem ao aplicar filtros de borda.

Exemplo: Imagem 32×32 com padding=1 se torna 34×34 temporariamente, então após convolução com filtro 3×3 e stride 1, volta a 32×32.

Pooling (Subamostragem)

Pooling reduz a dimensionalidade espacial combinando valores. Os tipos mais comuns são:

  • Max Pooling (2×2): Pega o valor máximo de uma janela 2×2. Reduz dimensão pela metade, retém features mais importantes.
  • Average Pooling: Média dos valores na janela. Suaviza o feature map, menos comum para visão.

Receptive Field (Campo Receptivo)

O receptive field é a área da imagem original que influencia um pixel de saída. Camadas CNNs sucessivas aumentam o receptive field exponencialmente, permitindo que neurônios profundos "vejam" contexto global.

Importância para contexto visual: Para classificar uma imagem como "contendo um rosto", o neurônio final precisa "ver" toda a imagem (receptive field = tamanho da imagem). Nos primeiros pixels de uma CNN profunda, cada neurônio só "vê" 3×3 pixels inicialmente, depois 5×5, depois 7×7, etc.

⚠️ Gotcha Comum: Arquiteturas rasas (poucas camadas) têm receptive field pequeno. Para classificar objetos grandes ou contextos globais, você precisa de CNN profunda ou campo receptivo adequadamente aumentado via stride/pooling.

Arquitetura Típica: Convolução → Pooling → Dense

Layout padrão e fluxo de dados através de uma CNN.

Uma CNN clássica segue este padrão:


[Input Image: 28×28×1 (ex: MNIST)]
           ↓
[Conv Block 1: 32 filtros 3×3, ReLU] → 28×28×32
           ↓
[Max Pool 2×2] → 14×14×32
           ↓
[Conv Block 2: 64 filtros 3×3, ReLU] → 14×14×64
           ↓
[Max Pool 2×2] → 7×7×64
           ↓
[Conv Block 3: 128 filtros 3×3, ReLU] → 7×7×128
           ↓
[Max Pool 2×2] → 3×3×128
           ↓
[Flatten] → 1152 neurônios
           ↓
[Dense: 256 neurônios, ReLU] → 256
           ↓
[Dropout: 0.5]
           ↓
[Output Dense: 10 neurônios, Softmax] → 10 (ex: 10 dígitos MNIST)

Fluxo de Dados e Feature Maps

Cada convolução detecta padrões, e o pooling reduz ruído e aumenta eficiência computacional. As camadas iniciais detectam features simples (bordas), e camadas progressivas combinam essas para detectar features complexas.

✅ Resultado: O padrão Conv → Pool → Conv → Pool estratifica a extração de características, desde baixo nível até alto nível de abstração.

Conexões Residuais (ResNet)

Arquiteturas modernas como ResNet (Residual Networks) adicionam "skip connections" que permitem treinar redes muito mais profundas. Sem skip connections, redes muito profundas (>100 camadas) sofrem do problema do desaparecimento do gradiente durante backpropagation.

Uma skip connection é uma simples adição: output = f(x) + x, onde f(x) é o bloco convolucional. Isso preserva gradientes e permite otimização eficiente.

Implementação Prática: PyTorch e TensorFlow

Código completo e testado para treinamento e inference.

Exemplo 1: CNN Simples em PyTorch (MNIST)

import torch
import torch.nn as nn
import torch.optim as optim
from torchvision import datasets, transforms

# 1. Definir arquitetura CNN
class SimpleCNN(nn.Module):
    def __init__(self):
        super(SimpleCNN, self).__init__()
        self.conv1 = nn.Conv2d(1, 32, kernel_size=3, padding=1)
        self.pool = nn.MaxPool2d(2, 2)
        self.conv2 = nn.Conv2d(32, 64, kernel_size=3, padding=1)
        self.fc1 = nn.Linear(64 * 7 * 7, 128)  # 28×28 → 14×14 → 7×7
        self.fc2 = nn.Linear(128, 10)
        self.relu = nn.ReLU()
        self.dropout = nn.Dropout(0.5)

    def forward(self, x):
        x = self.relu(self.conv1(x))
        x = self.pool(x)                        # 28×28 → 14×14
        x = self.relu(self.conv2(x))
        x = self.pool(x)                        # 14×14 → 7×7
        x = x.view(x.size(0), -1)               # Flatten
        x = self.relu(self.fc1(x))
        x = self.dropout(x)
        x = self.fc2(x)                         # Logits
        return x

# 2. Carregar dados MNIST
transform = transforms.Compose([
    transforms.ToTensor(),
    transforms.Normalize((0.5,), (0.5,))
])

train_dataset = datasets.MNIST(root='./data', train=True, 
                               download=True, transform=transform)
train_loader = torch.utils.data.DataLoader(train_dataset, 
                                          batch_size=64, shuffle=True)

# 3. Treinar modelo
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = SimpleCNN().to(device)
optimizer = optim.Adam(model.parameters(), lr=0.001)
criterion = nn.CrossEntropyLoss()

for epoch in range(5):
    for batch_idx, (data, target) in enumerate(train_loader):
        data, target = data.to(device), target.to(device)
        optimizer.zero_grad()
        output = model(data)
        loss = criterion(output, target)
        loss.backward()
        optimizer.step()
    print(f"Epoch {epoch+1} concluída")

# Salvar modelo
torch.save(model.state_dict(), 'cnn_mnist.pth')

Exemplo 2: Transfer Learning com ResNet (TensorFlow/Keras)

import tensorflow as tf
from tensorflow.keras.applications import ResNet50
from tensorflow.keras.preprocessing.image import ImageDataGenerator
from tensorflow.keras import layers, models

# 1. Carregar modelo ResNet50 pré-treinado em ImageNet
base_model = ResNet50(
    input_shape=(224, 224, 3),
    include_top=False,
    weights='imagenet'
)

# Congelar pesos da base (transfer learning)
base_model.trainable = False

# 2. Adicionar camadas customizadas no topo
model = models.Sequential([
    base_model,
    layers.GlobalAveragePooling2D(),
    layers.Dense(256, activation='relu'),
    layers.Dropout(0.5),
    layers.Dense(10, activation='softmax')  # 10 classes
])

# 3. Compilar
model.compile(
    optimizer='adam',
    loss='categorical_crossentropy',
    metrics=['accuracy']
)

# 4. Preparar dados com augmentação
train_datagen = ImageDataGenerator(
    rescale=1./255,
    rotation_range=20,
    width_shift_range=0.2,
    height_shift_range=0.2,
    horizontal_flip=True,
    zoom_range=0.2
)

# Assumindo dados em diretório com subdirs: train/class1, train/class2, ...
train_generator = train_datagen.flow_from_directory(
    'path/to/train',
    target_size=(224, 224),
    batch_size=32
)

# 5. Treinar (fine-tuning)
history = model.fit(
    train_generator,
    steps_per_epoch=100,
    epochs=5,
    verbose=1
)

# Salvar modelo
model.save('cnn_resnet50_finetuned.h5')

Exemplo 3: Data Augmentation Avançada (PyTorch)

from torchvision import transforms
from PIL import Image

# Estratégia de augmentação: rotação, crop, flip, desfoque, etc.
augmentation_transform = transforms.Compose([
    transforms.RandomRotation(15),
    transforms.RandomAffine(degrees=0, translate=(0.1, 0.1)),
    transforms.RandomHorizontalFlip(p=0.5),
    transforms.ColorJitter(brightness=0.2, contrast=0.2, saturation=0.2),
    transforms.RandomResizedCrop(size=224, scale=(0.8, 1.0)),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406],
                         std=[0.229, 0.224, 0.225])  # ImageNet stats
])

# Aplicar a transformações em imagem original
image = Image.open('sample_image.jpg')
augmented_images = [augmentation_transform(image) for _ in range(8)]

# Visualizar augmentações
import matplotlib.pyplot as plt
fig, axes = plt.subplots(2, 4, figsize=(12, 6))
for idx, aug_img in enumerate(augmented_images):
    ax = axes[idx // 4, idx % 4]
    ax.imshow(aug_img.permute(1, 2, 0))
    ax.set_title(f'Augmentation {idx}')
plt.show()

Exemplo 4: Modelo MobileNet para Dispositivos Edge

from tensorflow.keras.applications import MobileNetV2
from tensorflow.keras import layers, models

# MobileNet: versão leve para edge/mobile (1.3M parâmetros vs 25M de ResNet)
base_model = MobileNetV2(
    input_shape=(224, 224, 3),
    include_top=False,
    weights='imagenet'
)

# Arquitetura final
model = models.Sequential([
    base_model,
    layers.GlobalAveragePooling2D(),
    layers.Dense(128, activation='relu'),
    layers.Dropout(0.2),
    layers.Dense(10, activation='softmax')
])

# Compilar com otimizador leve
model.compile(
    optimizer='adam',
    loss='sparse_categorical_crossentropy',
    metrics=['accuracy']
)

# Info: MobileNet é ~12-20x menor que ResNet, adequado para:
# - SageMaker edge deployment
# - AWS Greengrass
# - Smartphones e IoT

print(f"Total parâmetros: {model.count_params()}")
# Output: Total parâmetros: 2301706 (muito menor!)

# Converter para TFLite para edge deployment
converter = tf.lite.TFLiteConverter.from_keras_model(model)
tflite_model = converter.convert()
with open('mobilenet_edge.tflite', 'wb') as f:
    f.write(tflite_model)

Arquiteturas Clássicas: LeNet, AlexNet, ResNet, VGG, MobileNet

Evolução histórica e características de cada arquitetura.

Arquitetura Ano Profundidade Parâmetros Accuracy (ImageNet) Caso de Uso
LeNet-5 1998 5 camadas 60K N/A MNIST, reconhecimento de dígitos. Histórico.
AlexNet 2012 8 camadas 60M 63.3% top-1 Breakthrough em ImageNet. Usava GPUs. Agora obsoleto.
VGG-16 2014 16 camadas 138M 71.3% top-1 Transferência, features gerais. Computacionalmente pesado.
ResNet-50 2015 50 camadas 25M 76.1% top-1 Padrão ouro: profundidade, eficiência, features ricas. Recomendado.
MobileNetV2 2018 53 camadas 3.5M 71.8% top-1 Edge, móvel, baixa latência. AWS IoT, Greengrass.
EfficientNet-B0 2019 Variável 5.3M 77.1% top-1 Melhor trade-off accuracy/eficiência. Recomendado para novos projetos.

Recomendações Práticas

  • Transfer Learning Geral: ResNet-50 (melhor custo-benefício) ou EfficientNet-B0 (latest)
  • Edge/Móvel: MobileNetV2 ou MobileNetV3
  • Máxima Accuracy (recursos ilimitados): ResNet-152, EfficientNet-B7
  • Legacy/Compatibilidade: VGG-16 (features universais, mas lento)

CNN vs Machine Learning Tradicional: Quando Usar Cada Um?

Trade-offs e escolhas arquiteturais.

Aspecto ML Tradicional (SVM, RF) CNN
Feature Engineering Manual (SIFT, HOG, etc.) - 80% do trabalho Automático (aprende features) - mais automático
Dados Necessários 100s-1000s de exemplos 1000s-100,000s (mais com transfer learning: 100s)
Computação CPU suficiente, rápido GPU recomendado, mais lento no treinamento
Accuracy (ImageNet style) ~50-60% top-1 75%+ (com deep learning)
Interpretabilidade Alta (feature importance) Baixa (caixa-preta, mas técnicas como CAM ajudam)
Implementação Rápida, simples (sklearn) Mais complexa, requer experiência

Matriz de Decisão

Use ML Tradicional se:

  • Você tem poucos dados (<100 exemplos)
  • Precisa de rápida implementação e produção
  • Requer interpretabilidade alta (requerimento regulatório)
  • Imagens são pequenas ou simples (ex: 32×32)
  • CPU apenas, sem GPU disponível

Use CNN se:

  • Você tem muitos dados ou acesso a transfer learning
  • Imagens são grandes, complexas ou naturais
  • Pode tolerar latência de treinamento
  • GPU/TPU disponível (AWS SageMaker, Vertex AI)
  • Precisa de máxima accuracy

Aplicação Financeira: OCR de Documentos e Classificação de Cheques

CNN para processamento de documentos bancários e transações.

Caso Real: Automatizar Processamento de Cheques

Um banco processa 50,000 cheques por dia. Cada cheque é escaneado e precisa ser automaticamente:

  • Classificado por tipo (pessoal, corporativo, pós-datado)
  • Extraído: Número da conta, valor, favorecido, assinatura
  • Validado: Assinatura legítima? Cheque duplicado?

Solução CNN:

import torch
import torch.nn as nn
from torchvision import transforms
from PIL import Image

# 1. Modelo CNN para classificação de cheques
class CheckClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 32, kernel_size=5, padding=2),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2),
            nn.Conv2d(32, 64, kernel_size=5, padding=2),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2),
            nn.Conv2d(64, 128, kernel_size=5, padding=2),
            nn.ReLU(inplace=True),
            nn.MaxPool2d(2, 2)
        )
        self.classifier = nn.Sequential(
            nn.Linear(128 * 28 * 28, 256),
            nn.ReLU(inplace=True),
            nn.Dropout(0.5),
            nn.Linear(256, 3)  # 3 classes: pessoal, corporativo, pós-datado
        )

    def forward(self, x):
        x = self.features(x)
        x = x.view(x.size(0), -1)
        x = self.classifier(x)
        return x

# 2. Processar imagem de cheque
model = CheckClassifier()
model.load_state_dict(torch.load('check_classifier.pth'))
model.eval()

check_image = Image.open('check_scan.jpg')
transform = transforms.Compose([
    transforms.Resize((224, 224)),
    transforms.ToTensor(),
    transforms.Normalize(mean=[0.485, 0.456, 0.406],
                         std=[0.229, 0.224, 0.225])
])

input_tensor = transform(check_image).unsqueeze(0)
with torch.no_grad():
    output = model(input_tensor)
    probabilities = torch.softmax(output, dim=1)
    predicted_class = torch.argmax(probabilities, dim=1).item()

class_names = ['Pessoal', 'Corporativo', 'Pós-datado']
print(f"Classificação: {class_names[predicted_class]} ({probabilities[0][predicted_class]:.2%})")

# 3. OCR para extrair campos (integrando com Textract AWS)
import boto3
textract = boto3.client('textract', region_name='us-east-1')

with open('check_scan.jpg', 'rb') as f:
    response = textract.detect_document_text(
        Document={'Bytes': f.read()}
    )

# Extrair valores de campos específicos
extracted_text = [block['Text'] for block in response['Blocks']
                   if block['BlockType'] == 'LINE']
print("Texto extraído:", extracted_text)
