Vision Transformers (ViT): Revolucionando Visão Computacional

Por que Transformers também dominam visão, não apenas texto.

Historicamente, CNNs dominavam visão computacional. Mas em 2021, o paper "An Image is Worth 16x16 Words" (Dosovitskiy et al.) mostrou que Transformers puro (sem convolução) conseguem resultados superiores se treinados em escala suficiente.

Conceito Central: Dividir Imagem em Patches

Em vez de aplicar convoluções em pixels, ViT divide a imagem em patches pequenos (ex: 16×16 pixels), os trata como "tokens" (analogamente a palavras em texto), e aplica o mecanismo de self-attention dos Transformers.


Imagem Original: 224×224×3
         ↓
Patches: 16×16 = 14×14 = 196 patches
Cada patch → embedding 768-dim
         ↓
196 embeddings + positional encoding
         ↓
Transformer Encoder (12+ camadas, 12 heads)
         ↓
[CLS] token → representação global
         ↓
MLP Head → Classe (1000 classes ImageNet)

Vantagens vs CNNs

Vision Transformers (ViT)

  • Global receptive field desde início
  • Paralelizável completamente
  • Melhor escalabilidade com dados
  • Transferência melhor entre domínios
  • Mais parâmetros = mais dados necessários

CNNs Tradicionais

  • Receptive field cresce gradualmente
  • Inductive bias espacial (filtros)
  • Funciona bem com dados pequenos
  • Menos parâmetros para mesma accuracy
  • Mais interpretável (filtros detectam features)

Variantes Modernas

  • DeiT (Data-efficient Image Transformers): ViT otimizado para dados menores com distilação de conhecimento
  • CLIP: Vision Transformer + Text Transformer treinados em 400M imagens + captions. Excelente para zero-shot classification
  • DINO: Self-supervised ViT. Treina sem labels, features excelentes para downstream tasks
✅ Recomendação Prática: Use ViT quando tiver 100K+ imagens. Caso contrário, CNNs (ResNet) + data augmentation é melhor.

BERT & Large Language Models: Pré-treinamento Bidirecional

De BERT a modelos como Claude e GPT: evolução do pré-treinamento.

BERT (Bidirectional Encoder Representations from Transformers) revolucionou NLP em 2018 ao demonstrar que pré-treinar Transformers bidirecionalmente em corpus enorme (Wikipedia + BookCorpus) e depois fazer fine-tune em tarefas específicas produzia state-of-the-art em praticamente todas as tarefas NLP.

Pré-treinamento BERT: Masked Language Modeling

BERT treina em 2 tarefas não supervisionadas:

Masked Language Modeling (MLM)

Mascarar 15% das palavras e prever qual era. Força o modelo a usar contexto bidirecional.

Input: "The [MASK] sat on the mat"
Predict: cat, dog, bird, ...

Next Sentence Prediction (NSP)

Dados 2 sentenças, prever se segunda segue a primeira. Entender relacionamento entre sentenças.

S1: "I like pizza"
S2: "It is delicious" → IsNext=True

Fine-tuning BERT em Tarefas Específicas

Após pré-treinamento, adapta-se BERT congelando ou decongelando pesos:

from transformers import BertForSequenceClassification, BertTokenizer
import torch

# 1. Carregar modelo BERT pré-treinado
tokenizer = BertTokenizer.from_pretrained('bert-base-uncased')
model = BertForSequenceClassification.from_pretrained(
    'bert-base-uncased',
    num_labels=2  # Binary classification: positive/negative
)

# 2. Preparar dados
texts = ["I love this movie!", "Terrible film, waste of time"]
labels = [1, 0]  # positivo, negativo

encoding = tokenizer(
    texts,
    return_tensors='pt',
    padding=True,
    truncation=True,
    max_length=128
)

# 3. Fine-tune
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)

for epoch in range(3):
    optimizer.zero_grad()
    outputs = model(**encoding, labels=torch.tensor(labels))
    loss = outputs.loss
    loss.backward()
    optimizer.step()
    print(f"Epoch {epoch}, Loss: {loss.item():.4f}")

# 4. Inference
model.eval()
test_text = "Amazing performance!"
test_encoding = tokenizer(test_text, return_tensors='pt', padding=True)
with torch.no_grad():
    outputs = model(**test_encoding)
    predictions = torch.softmax(outputs.logits, dim=1)
    sentiment = "Positive" if predictions[0, 1] > 0.5 else "Negative"
    confidence = predictions[0].max().item()
print(f"Sentiment: {sentiment} (confidence: {confidence:.2%})")

Evolução: De BERT a GPT-4

Modelo Ano Parâmetros Direção Pré-treinamento Dados
BERT 2018 340M Bidirecional MLM + NSP 3.3B tokens
GPT-2 2019 1.5B Unidirecional (left-to-right) Predição de próximo token 40B tokens
GPT-3 2020 175B Unidirecional Predição de próximo token 300B tokens
Claude (Anthropic) 2023 100B+ Unidirecional (otimizado para dialog) RLHF (Reinforcement Learning from Human Feedback) Trillions tokens
GPT-4 2023 ~1.8T (estimado) Unidirecional Predição + RLHF Trillions tokens
ℹ️ Tendência: Modelos modernos (GPT-3+, Claude) usam pré-treinamento unidirecional porque geração de texto é tarefa next-token-prediction. BERT é melhor para compreensão (fine-tune tarefas).

Modelos Generativos: Diffusion Process & Stable Diffusion

Como gerar imagens a partir de texto com difusão.

Visão Geral: Diffusion Models

Modelos de difusão funcionam em 2 fases:


FASE 1: Forward Diffusion Process (Treinamento)
Imagem original → Adicionar ruído gradualment → Ruído puro
        ↓
Treinar modelo para "denoising": dado ruído em etapa t, 
prever qual ruído foi adicionado

FASE 2: Reverse Diffusion Process (Geração)
Ruído puro → Remover ruído gradualmente → Imagem original
        ↓
Usar modelo denoiser aprendido para reverter difusão

Stable Diffusion: Implementação Prática

from diffusers import StableDiffusionPipeline
import torch

# 1. Carregar modelo Stable Diffusion pré-treinado
model_id = "runwayml/stable-diffusion-v1-5"
pipe = StableDiffusionPipeline.from_pretrained(
    model_id,
    torch_dtype=torch.float16,
    revision="fp16"
)

# Mover para GPU
pipe = pipe.to("cuda")

# 2. Gerar imagem a partir de texto (prompt)
prompt = "A serene Japanese garden with koi fish, sunset, oil painting"
negative_prompt = "blurry, low quality, distorted"

with torch.autocast("cuda"):
    image = pipe(
        prompt,
        negative_prompt=negative_prompt,
        num_inference_steps=50,  # Mais steps = melhor qualidade (mais lento)
        guidance_scale=7.5,       # Força de prompt (higher = mais fiel ao prompt)
        height=512,
        width=512,
        generator=torch.Generator("cuda").manual_seed(42)  # Reproducibilidade
    ).images[0]

image.save("garden.png")

# 3. Fine-tuning em estilo customizado (dreambooth)
# Se quiser gerar imagens no seu estilo ou com pessoa/objeto específico:
# Usar método "DreamBooth" para adaptar modelo com ~5-10 imagens

# 4. Deploy em SageMaker
# Modelo precisa: ~10GB VRAM (A100), ~5 segundos por geração
# Usar SageMaker Endpoint com GPU ml.g4dn.xlarge ou ml.a10g.xlarge

Prompt Engineering: Arte & Ciência de Comunicar com LLMs

Técnicas comprovadas para melhorar outputs de modelos.

Técnicas de Prompt Engineering

Few-Shot Prompting

Fornecer exemplos antes de fazer pergunta real.

Exemplos de sentiment analysis:
"I love this" → Positive
"Hate this" → Negative
"This movie is OK" → ?

Chain-of-Thought

Pedir modelo raciocinar passo a passo.

Ruim: "Qual é 7 × 8 ÷ 2?"
Bom: "Resolva passo a passo: 7 × 8 ÷ 2"
Melhora acurácia em ~40%

Role-based Prompts

Atribuir papel ao modelo (ex: "Você é especialista em finanças").

"Como especialista bancário, explique
risco de mercado para iniciante"

Temperature & Top-K

Controlar criatividade vs determinismo.

Temperature=0: Determinístico
Temperature=1: Criativo
Top-K=40: Considerar 40 tokens mais prováveis

Exemplo: Prompt Estruturado para Análise Financeira

import anthropic

client = anthropic.Anthropic()

# Prompt estruturado (melhor prática)
prompt = """
Você é um analista de risco financeiro sênior com 20 anos de experiência.

Analise o seguinte relatório de transação e identifique:
1. Score de risco (0-100)
2. Padrão suspeito específico
3. Ação recomendada

Contexto:
- Cliente: João Silva, conta desde 2018, histórico limpo
- Transação: Transferência $50,000 para conta pessoa jurídica nova
- Localização destino: Paraíso Fiscal
- Hora: 3:45 AM
- Frequência: Primeira grande transferência em 6 anos

Analise em português, de forma concisa.
"""

message = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": prompt}
    ]
)

print(message.content[0].text)

# Output esperado (exemplo):
# Score de risco: 78
# Padrão: Transação atípica em valor, destino alto-risco, hora inusual
# Ação: Contato com cliente para confirmar legitimidade antes de processar
✅ Melhores Práticas:
• Seja específico e detalhado
• Estruture com exemplos
• Peça raciocínio passo-a-passo
• Use temperatura adequada (0 para análise, 0.7 para criatividade)
• Teste e itere múltiplas versões

Model Compression: Quantização, Pruning & Destilação

Reduzir tamanho e latência sem sacrificar muita qualidade.

Técnicas de Compressão

Quantização

Converter pesos de float32 → int8 ou float16

Redução: 4x tamanho
Perda: ~1-2% accuracy
Ganho: 3-4x latência menor

Pruning

Remover neurônios/pesos pouco importantes

Redução: 30-50% parâmetros
Perda: ~2-5% accuracy
Ganho: 2x latência menor

Destilação

Modelo pequeno aprende de modelo grande

Redução: 10-100x parâmetros
Perda: ~3-10% accuracy
Ganho: 10-50x latência menor

Implementação: Quantização INT8 com PyTorch

import torch
from torch.quantization import quantize_dynamic
from transformers import AutoTokenizer, AutoModelForSequenceClassification

# 1. Carregar modelo
model_name = "distilbert-base-uncased-finetuned-sst-2-english"
model = AutoModelForSequenceClassification.from_pretrained(model_name)
tokenizer = AutoTokenizer.from_pretrained(model_name)

# 2. Quantizar dinamicamente (pesos: int8, ativações: float32)
quantized_model = quantize_dynamic(
    model,
    {torch.nn.Linear},  # Quantizar camadas lineares
    dtype=torch.qint8
)

# 3. Comparar tamanho
print(f"Original size: {sum(p.numel() for p in model.parameters()) / 1e6:.1f}M params")
print(f"Quantized size: {sum(p.numel() for p in quantized_model.parameters()) / 1e6:.1f}M params")

# Salvar modelo quantizado
torch.jit.save(torch.jit.script(quantized_model), "model_quantized.pt")

# 4. Inference (3-4x mais rápido)
text = "I love this movie!"
inputs = tokenizer(text, return_tensors="pt")
with torch.no_grad():
    outputs = quantized_model(**inputs)
    prediction = torch.softmax(outputs.logits, dim=1)
    print(f"Confidence: {prediction.max().item():.2%}")

# 5. Deploy em SageMaker com modelo quantizado
# Modelo reduz de 270MB → 67MB
# Latência: 200ms → 50ms (4x mais rápido!)

Benchmark: Trade-offs

Técnica Redução de Tamanho Redução de Latência Perda de Accuracy Implementação
Sem Otimização 1x 1x 0% Trivial
Quantização INT8 4x 3-4x 1-2% Fácil (1 linha PyTorch)
Pruning 50% 2x 2x 2-5% Médio (requer retrainamento)
Destilação de 12→6 camadas 50% 2x 3-8% Difícil (treinar novo modelo)
Combinado (INT8+Pruning) 8x 6-8x 3-7% Complexo (múltiplas etapas)
ℹ️ Recomendação: Para produção com latência <100ms, use quantização + pruning combinados. Para latência crítica (<50ms), considere destilação em modelo menor.

Matriz de Arquiteturas: CNN vs RNN vs Transformer

Quando usar cada uma em produção.

Aspecto CNN RNN/LSTM Transformer
Melhor Para Imagens, visão Sequências temporais, streaming NLP, sequências complexas
Latência Treino Rápida (horas) Média (dias) Lenta (semanas+)
Latência Inferência Muito rápida (<10ms) Rápida (~50ms) Média (~200ms)
Memória de Contexto Receptive field local Limitado (~100 tokens) Ilimitado (até atender GPU)
Escalabilidade Lineares com tamanho imagem Linear com sequência Quadrática com sequência
Dados Necessários 1K-10K (com transfer learning) 10K-100K 100K-10M (ou transfer learning)
Paralelização Completa Sequencial (lenta) Completa
Frameworks Recomendados PyTorch, TensorFlow, MXNet PyTorch, TensorFlow HuggingFace Transformers, PyTorch
Deploy Recomendado SageMaker, TFServing, ONNX Lambda (small), SageMaker SageMaker, vLLM (LLM), Replicate

Matriz de Decisão: Qual Usar?

Problema: Classificar imagens de produtos e-commerce → CNN (ResNet-50 com transfer learning)
Problema: Prever preço de ação nos próximos 30 dias → LSTM bidirecional
Problema: Responder perguntas em português sobre documento → Transformer (BERT-pt)
Problema: Gerar descrição de imagem → Vision Transformer + Transformer de texto (multimodal)

Production Deployment: SageMaker, Inferência & Monitoramento

Levar modelos para produção com baixa latência e alta confiabilidade.

Arquitetura de Deployment em SageMaker

import sagemaker
from sagemaker.pytorch.model import PyTorchModel
import boto3

# 1. Preparar modelo para deploy
# - Salvar weights otimizados (quantizado, se necessário)
# - Criar inference.py (script customizado de inference)
# - Packagiar em tar.gz com código + modelo

# 2. Deploy no SageMaker
role = "arn:aws:iam::YOUR_ACCOUNT:role/SageMaker-Role"
session = sagemaker.Session()
bucket = session.default_bucket()

pytorch_model = PyTorchModel(
    model_data="s3://your-bucket/model.tar.gz",
    role=role,
    entry_point="inference.py",
    source_dir="./",
    framework_version="2.0",
    py_version="py39",
    instance_type="ml.g4dn.xlarge"  # GPU para LLMs/Transformers
)

# Deploy com auto-scaling
predictor = pytorch_model.deploy(
    initial_instance_count=2,
    instance_type="ml.g4dn.xlarge",
    endpoint_name="bert-sentiment-endpoint",
    wait=True
)

# 3. Configurar auto-scaling
autoscaling = boto3.client('application-autoscaling')
autoscaling.register_scalable_target(
    ServiceNamespace='sagemaker',
    ResourceId=f'endpoint/bert-sentiment-endpoint/variant/AllTraffic',
    ScalableDimension='sagemaker:variant:DesiredInstanceCount',
    MinCapacity=2,
    MaxCapacity=10
)

autoscaling.put_scaling_policy(
    PolicyName='bert-scaling-policy',
    ServiceNamespace='sagemaker',
    ResourceId=f'endpoint/bert-sentiment-endpoint/variant/AllTraffic',
    ScalableDimension='sagemaker:variant:DesiredInstanceCount',
    PolicyType='TargetTrackingScaling',
    TargetTrackingScalingPolicyConfiguration={
        'TargetValue': 70.0,
        'PredefinedMetricSpecification': {
            'PredefinedMetricType': 'SageMakerVariantInvocationsPerInstance'
        }
    }
)

# 4. Usar endpoint em produção
import json

# Exemplo 1: Batch prediction
data = [
    {"text": "I love this product!"},
    {"text": "Terrible quality"},
    {"text": "Average"}
]

for item in data:
    response = predictor.predict(
        json.dumps({"inputs": item["text"]}),
        initial_args={"ContentType": "application/json"}
    )
    prediction = json.loads(response)
    print(f"Text: {item['text']} → Sentiment: {prediction['sentiment']}")

# Exemplo 2: Real-time inference com latência tracking
import time

start = time.time()
response = predictor.predict(
    json.dumps({"inputs": "Best purchase ever!"}),
    initial_args={"ContentType": "application/json"}
)
latency_ms = (time.time() - start) * 1000
print(f"Latency: {latency_ms:.1f}ms")  # Target: <100ms

# 5. Monitoramento em produção
cloudwatch = boto3.client('cloudwatch')
cloudwatch.put_metric_data(
    Namespace='CustomML',
    MetricData=[
        {
            'MetricName': 'EndpointLatency',
            'Value': latency_ms,
            'Unit': 'Milliseconds'
        },
        {
            'MetricName': 'InferenceAccuracy',
            'Value': 94.2,  # Acurácia em dados reais
            'Unit': 'Percent'
        }
    ]
)

# 6. Limpeza (quando não mais necessário)
predictor.delete_endpoint()

Best Practices para Produção

Performance

  • Batch prediction onde possível
  • Usar quantização para latência
  • Caching de embeddings/outputs
  • Model warm-up antes de produção

Confiabilidade

  • Auto-scaling de endpoints
  • Monitoramento de drift de dados
  • Fallback para modelo anterior
  • Alertas de latência/acurácia
⚠️ Custos em Produção: GPU ml.g4dn.xlarge custa ~$1.06/hora. Para LLMs com muitas inferências, considere batch processing (SageMaker Batch Transform) para reduzir custos em 50%+.
